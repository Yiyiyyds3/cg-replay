## ① feat/unpack-catsystem2 → main（3 笔）

**关键事实**：本分支的 `internal/unpack/catsystem2.go:25-29` 只注册 `ParseArchive`，**没有 `OpenReader`**；KIF 条目读取仍走通用 seek+zlib。②的 6380d59 才补上 `kif.Open + arc.Read`，其提交注释原话是「通用读取只做 zlib，读出来是密文」。

- **CS2 解包在本 PR 单独不可用** `internal/unpack/catsystem2.go:25-29`
  表述必须是「本 PR 单独落地时，解出的 `.cst` 是密文，依赖 ② 的 `OpenReader` 才通」，**不能**写成「真机解出 0 文件」。
  修法：PR 描述写明依赖关系；或把 ② 的 `OpenReader`（assets.go + engine.go 两处）前移到本 PR。
- **BGI 嗅探分支永不命中** `internal/unpack/sniff.go:22,37`
  `head := make([]byte, 16)` + `io.ReadFull` 只读 16 字节，而 `"BurikoCompiledScript"` 是 20 字节，`HasPrefix` 恒 false；提交信息声称「按文件头识别 BGI 编译脚本」。改成读 32 字节。

  两处都取 `sniffHint(archives[0])`——排序后的第一个归档，不是失败那个；真机 20 个 `.xp3` 里混 1 个 ZIP 时，提示会说好文件的格式。修法：用 `err` 里带的归档路径反查。
- **一个坏归档毁掉整批** `internal/unpack/assets.go:55-60`
  循环里首个 `parse` 失败就 `s.close(); return nil, err`，整批归档一起废；调用方 `unpack.go:187-200` / `:256-266` 只能把它当成「这个游戏解不开」。②才改成逐个容错（同「依赖 ②」）。
- **未设 `Dynamic`，动态引用静默吞** `internal/unpack/engine.go:27`
  字段注释写的是「有动态引用（运行时拼文件名）→ 闭包必然不全」，全仓唯一写入点是 `internal/unpack/kirikiri.go:40`；`unpack.go:297-299` 的告警只在 `info.Dynamic` 为真时才发。CS2 适配器从不填 → 闭包不全且零告警。
- **「四引擎全部可解」在登记侧不成立** `internal/unpack/unpack.go:11`

- **CS2 预览把密文说成 adlr 校验和** `desktop/frontend/src/EventGrid.tsx:790-791`
  只要 `unpackPlan.encrypted > 0` 就打印「N 个条目带 adlr 校验和（乱码时可选解密方案）」，并在 `:798` 起提供 XOR 方案。KIF 是 Blowfish 全条目加密、与 adlr 无关，用户照提示选 XOR 会把密文再 XOR 一遍落盘。修法：按引擎区分文案；CS2 明确说「需要官方密钥，当前不支持」。

- **`spine_stats` 崩溃点与错误形状** `tools/unity_cg_export.py:189-193,211-223` ↔ `unitycg.go:66-73`
