# 03 · 常见问题与排错手册

> 配套：01_上手指南、02_工具使用说明（同目录）。本手册只收录**真实踩过的坑**，每条按「现象 → 判断方法（可复制命令）→ 处理动作」组织。
> 引用格式 `文件:行`，均指本仓库内文件；命令默认在仓库根目录的 PowerShell 里执行，`$repo` 先按 docs/16_人工抽检验收SOP.md:20 的方式设置。
> 手册不含任何编造的命令输出；标注「通用命令」的是标准 PowerShell 写法，输出以实跑为准。

## 1. 「跑不出图 / 目录空」类

### 1.1 rmmz 加密图：画廊/预筛里全是「加密图不可渲染」

- **现象**：画廊里某款挂红色 chip「加密图不可渲染」，缩略图区只有占位块；或预筛报告写「CG 族里没有明文图，只剩加密图 N 个（.rpgmvp/.png_），机器读不到像素」。
- **真实案例**：本库 53 款里 `encrypted` 状态 21 款、全是 rmmz（tools/review-gallery/README.md:220）；rmmz 预筛 37 款里 19 款 CG 族一张明文图都没有（tools/review-prescreen/README.md:172）。单款实例：Scars of Summer After 加密图 3987 个（reports/人工抽检/预筛可疑_rmmz.md:1346）、Unholy_maiden 4182 个（同文件:1401）、呪いの鎧 3385 个（同文件:1569）。
- **判断方法**（通用命令）：

```powershell
# 数一款游戏里的加密图（.rpgmvp/.png_/.jpg_）
$root = "E:\...\<游戏名>"
Get-ChildItem $root -Recurse -Include *.rpgmvp,*.png_,*.jpg_ -File |
  Measure-Object | Select-Object Count

# 对照明文 png 有多少张
Get-ChildItem $root -Recurse -Filter *.png -File |
  Measure-Object | Select-Object Count
```

- **处理动作**：
  1. 回放库本身**能读加密图**：`.rpgmvp` 由 `decode.DecodeImage` 实测可正常解码，`System.json` 的 `encryptionKey` 齐全即可（reports/第1批_RPG_Maker_扫描验证_2026-11-04.md:38、:83）。所以「回放链路」与「画廊预览」是两条路，别混淆。
  2. 要肉眼验收（画廊/预筛只吃明文 png），先走项目内解密/导出链路产出明文 png，再把清单里该款 `image_root` 指到明文目录后重建画廊（docs/16_人工抽检验收SOP.md:66，tools/review-gallery/README.md:220）。
  3. 重建画廊命令（docs/16_人工抽检验收SOP.md:26-27）：

```powershell
go build -o tools/review-gallery/review-gallery.exe ./tools/review-gallery
go run ./tools/review-gallery
```

### 1.2 Unity 款扫描直接 fail：缺 cg-index.json / 一张 CG 都没有

- **现象 A**：审计报 `scan_error`，原文 `读 CG 索引失败：open …\cg-index.json: The system cannot find the file specified.`，且明确标 **引擎级**——`ScanUnity 依赖预置 cg-index.json`（reports/游戏库验收_批3报告.md:282）。
- **现象 B**：导出成功但 `cg=0（孤儿 png N / text M）`，判定 `fail（export_zero_cg）`（reports/游戏库验收_unity导出批1报告.md:27-30）。
- **判断方法**：

```powershell
# 看导出目录里有没有索引与图
Get-ChildItem "D:\UCGR_UnityCG\<游戏名>" | Select-Object Name,Length
Test-Path "D:\UCGR_UnityCG\<游戏名>\cg-index.json"
```

- **处理动作**：
  1. Unity 款必须**先用导出器**生成索引再扫：`python tools/unity_cg_export.py --game "<游戏目录（含 <Game>_Data）>" --out D:\UCGR_UnityCG\<游戏>`（reports/游戏库验收_总报告.md:57、:110）。
  2. 导出前先 dry-run 看容器命中情况（reports/游戏库验收_批3报告.md:226）：

```powershell
python tools/unity_cg_export.py --game "<同上>" --out "D:\UCGR_UnityCG\<游戏名>" --dry-run
```

  3. 大款要**全量传容器参数**并配 `--still-regex` 锚定 CG 纹理名（`^` 锚定）：如 Swarm Bunker 单容器 3834 tex + `--still-regex ^(WomanA_H\|WomanB_H\|GirlB_H)`（reports/游戏库验收_unity导出批3报告.md:26）；正则没锚定会混进无关纹理。
  4. `cg=0` 且孤儿 png 全是 UI/字体纹理 = 该款纹理命名里没有 CG 命名族，属 E 形态维持 fail（GensouBrothel 实测：reports/游戏库验收_unity导出批3报告.md:22；docs/15_游戏库验收_GitHub管理.md:287），别死磕，按 docs/14_游戏库全量验收_执行计划.md:164 建 Issue 跳过。
  5. IL2CPP/解密款特殊：LifeguardHolic 是「解密 → 内层 Lifeguard Holic（IL2CPP）」两层结构，要确认导出的是**内层真实 CG** 而非解密中间产物（docs/16_人工抽检验收SOP.md:105）。

### 1.3 rmmz 扫出 0 事件：「没有识别到图片演出」

- **现象**：扫描成功但事件数为 0，或报「没有识别到图片演出」。
- **根因（实测 3 款）**：图片由插件/脚本驱动——`code 231 Show Picture` 为 0 而 `code 355 Script` 大量出现，图片名由插件运行时状态决定，静态 `Map*.json` 里没有（reports/第1批_RPG_Maker_扫描验证_2026-11-04.md:26-34）。典型插件函数：`this.cgLoad`、`this.picsChange2`、`$w.startZm`（同文件:30-32）。
- **判断方法**：修复后适配器会给出可行动诊断，直接列出高频插件函数名（同文件:52-56）。复扫命令：

```powershell
go run ./cmd/library-audit -group "<评价组>" -batch <批次名> -out reports/audit
```

（命令形态见 reports/游戏库验收_批3报告.md:199。）
- **处理动作**：确认诊断里带插件函数名 = 插件驱动型，需要插件级解析器，**本轮不投入**（README 硬约束「不做通用引擎模拟器」，reports/第1批_RPG_Maker_扫描验证_2026-11-04.md:77），按待定处理，别按普通款反复重跑。
- **注意排除误判**：这 3 款不是解密问题也不是路径问题——`.rpgmvp` 能解码、`www/data`/`www/img` 都定位正确（同文件:38-39）。

### 1.4 缺主程序口令的归档解不开

- **现象**：`ucgr unpack` 或摄入链路在加密归档上停住；流水线红线是「S1：发现加密/混淆 → 暂停，先解决解密」（docs/05_流水线设计.md:30）。
- **判断方法**：先查该游戏目录有没有解包说明 md——本库 47 款里 34 款有，其中「引擎/归档/口令均为上一次实测结论」（reports/引擎分布复核报告_2026-10-15.md:64）：

```powershell
Get-ChildItem "<游戏目录>" -Filter *.md -Recurse | Select-Object FullName
```

- **处理动作**：
  1. 有说明 → 按 md 里记录的口令解包：`ucgr unpack <归档> [--out 目录] [--key 口令] [--limit N]`（cmd/ucgr/main.go:119，CatSystem2 KIF）。
  2. 没说明 → 口令要自己实测（strings 主程序/配置），**库不存口令**：数据库只存 `key_hint` 口令提示，明确「不存口令本身」（docs/02_数据模型与包格式规范.md:277、:391）；冷归档口令也是「本地保管，仅存 key_hint」（docs/01_需求规格说明书.md:253、docs/06_客户端功能与交互设计.md:164）。
  3. 密钥/掩码类引擎（如 XP3 `adlr`、BGI 变体）标 `encrypted=true` + `key_hint`，密钥不进 IR、不进包（docs/04_引擎适配器接口规范.md:99）。
  4. 单款卡死超过 15 分钟按 docs/14_游戏库全量验收_执行计划.md:164 的「禁止死磕」规则建 Issue 跳过。

### 1.5 目录明明有图，画廊却说「目录缺失 / 无明文图片 / 缩略图全空」

- **现象与判断**：画廊 section 有四态状态 chip——`ok` / `missing_dir`（目录被移走、盘符没挂）/ `encrypted` / `no_images`（tools/review-gallery/README.md:211-218），每款标题条下都有可整段选中的 cg-index 绝对路径，先用 `Test-Path` 核对：

```powershell
Test-Path "<画廊标题条上的那个绝对路径>"
```

- **处理动作**：
  1. `missing_dir` → 把清单里的 `cg_dir`/`source_real_path` 改到实际位置再重建。
  2. 缩略图全空但路径存在 → 个别浏览器在 `file://` 下拦本地子资源，换 Chrome/Edge 打开即可（tools/review-gallery/README.md:230）。
  3. 扫描根探测错位 → rmmz 源目录按 `img\pictures → www\img\pictures → img\cg → img → www\img` 顺序探测（docs/16_人工抽检验收SOP.md:53，tools/review-gallery/README.md:106-109）；更新档+本体双份目录会扫出**两个 img 根**、重复率被抬高（人柱阿拉卡实测 note，reports/人工抽检/预筛可疑_rmmz.md:1553），在清单里用 `image_root` 显式指定正确的那个。

## 2. 「图能出但不对」类

> 判定口径与降级规则见 docs/16_人工抽检验收SOP.md §5-§6（:108-154）：裁切错位/半张图 → `crop_misalign`、重复率≥5% → `duplicate_frames`、透明通道全黑 → `alpha` 等（docs/16_人工抽检验收SOP.md:193）。
> 「工具层 pass = 管线跑通并产出可见图，不等于画质达标」（docs/16_人工抽检验收SOP.md:10-11）。

### 2.1 裁切错位 / 半张图

- **现象**：人物被切掉一半、图层相对位置不对。
- **判断方法**：rmmz 画面是立绘/差分**叠加合成帧**，先确认是「导出错」还是「合成语义差」——MV 差分立绘静态提取会同层半透明叠加、出现轻微重影，这是既定保真度边界（reports/第1批_RPG_Maker_扫描验证_2026-11-04.md:91），不算错位。
- **处理动作**：真错位记 `crop_misalign`（PARTIAL，docs/16_人工抽检验收SOP.md:149），把 2~3 张问题图拷进 `reports/人工抽检/证据/<游戏名>/` 并写复现命令（同文件:164-171）。

### 2.2 透明通道全黑

- **现象**：半透明边缘发黑、整图黑底。
- **判断方法**：注意预筛的 alpha 口径——预筛**按白底合成**再取灰度（防止全透明像素被当黑、spine 透明边拉平方差），所以「预筛说正常」不等于 alpha 没问题（tools/review-prescreen/README.md:147）。
- **处理动作**：人工确认后记 `alpha`（PARTIAL，docs/16_人工抽检验收SOP.md:152）；rmmz 款重点查叠加层边缘（docs/16_人工抽检验收SOP.md:57）。

### 2.3 空白帧（含「其实是正常黑幕」的误报）

- **现象**：预筛报「空白帧 N 张（var=0.0）」。
- **判断方法**：先跑体积筛（docs/16_人工抽检验收SOP.md:133-136 原命令）：

```powershell
# 疑似空帧/占位图（<2KB 的 PNG）
Get-ChildItem "D:\UCGR_Work\unitycg\<游戏名>\cg" -Recurse -Filter *.png |
  Where-Object Length -lt 2KB |
  Select-Object Name,Length
```

- **真实案例里要区分三种**：
  1. **真占位图**：IdealEvesRoom 15/17 张 <5KB、均单图 5.8KB（reports/人工抽检/预筛可疑.md:40、:205-215）；
  2. **合法黑幕/背景**：Risty 的 `blackBG.png (var=0.0)`（reports/人工抽检/预筛可疑_rmmz.md:1208）、女主角（大雷）的 `背景_黒幕.png (var=0.0)`（同文件:1683-1687）——文件名就是黑幕，属正常素材；
  3. **预筛口径漏报**：32x32 网格方差判据会漏「大白底 + 一行小字」，MasyouSyoujo 的 `img_011g` 方差 0.0、肉眼看是白底一行台词（tools/review-prescreen/README.md:145-146）——这种归「需人工确认」，不是自动判死。
- **处理动作**：全黑全白且非黑幕命名 → `blank_frame`；黑幕/背景放行；部分覆盖内容图降级为 note。

### 2.4 重复帧

- **判断方法**（docs/16_人工抽检验收SOP.md:126-131 原命令，按 MD5 分组）：

```powershell
# 重复帧：按 MD5 分组，Count>1 即重复（可先看比例再人工确认是不是剧情复用图）
Get-ChildItem "D:\UCGR_Work\unitycg\<游戏名>\cg" -Recurse -Filter *.png |
  Get-FileHash -Algorithm MD5 |
  Group-Object Hash |
  Where-Object Count -gt 1 |
  Sort-Object Count -Descending |
  Select-Object Count,Name
```

- **两种重复要分开**：预筛的 `dup_groups` 是 8x8 dHash **近似重复**（同模板换数字也会撞桶，GoblinSword 的 `CGSample01..20` 就是布局相同只改角标），`exact_dup_*` 才是字节级 SHA-1 同一份文件；近似多、完全少 = 模板复用，两个都高 = 纯冗余（tools/review-prescreen/README.md:142-144）。极端实例：KanzenChikan `0/0.png = 1/1.png = 10/10.png = …等 15 张`、冗余率 82.3%（reports/人工抽检/预筛可疑.md:51、:221）。
- **处理动作**：重复率 ≥5% 记 `duplicate_frames`（PARTIAL，docs/16_人工抽检验收SOP.md:150）；确认是剧情复用图的记 note 放行。

### 2.5 分辨率不一致 / 尺寸离群

- **判断方法**（通用命令，按像素尺寸统计；rmmz 款把路径换成 `…\www\img\pictures`）：

```powershell
# 按像素尺寸统计全目录分布（众数 + 离群一眼看出）
Add-Type -AssemblyName System.Drawing
Get-ChildItem "D:\UCGR_Work\unitycg\<游戏名>\cg" -Recurse -Filter *.png |
  ForEach-Object {
    $img = [System.Drawing.Image]::FromFile($_.FullName)
    "{0}x{1}" -f $img.Width, $img.Height
    $img.Dispose()
  } |
  Group-Object | Sort-Object Count -Descending |
  Select-Object Count, Name | Select-Object -First 15
```

- **真实案例里要先排除正常情况**：
  1. **UI/血条贴图混进 CG 族**：LoveConfessions 的 `battle/battle_hp.png` 等极小图、SwarmBunker 168 张 320x180 离群（reports/人工抽检/预筛可疑.md:106、:86-87）——rmmz 的 `actorhud/battlehud` 族同理（UI_Meter/Face_N，reports/人工抽检/预筛可疑_rmmz.md:983-999 一带），属于素材本来如此；
  2. **spine 图集本来就该大**：GoblinSword `EventCG01_Atlas0.png (4096x2112)`（reports/人工抽检/预筛可疑.md:146）；
  3. **真异常**：IdealEvesRoom 混进 32x32 小图（reports/人工抽检/预筛可疑.md:44-45）。
- **处理动作**：同款主图分辨率应一致且无 <256px 糊图充当 CG（docs/16_人工抽检验收SOP.md:110）；确认异常后记 note 或降级。批量复核可直接跑预筛工具只看这一款（tools/review-prescreen/README.md:39）：

```powershell
go run ./tools/review-prescreen -root "D:\UCGR_Work\unitycg" -only "<游戏名>"
```

### 2.6 spine 三件套不配对

- **现象**：`.json` / `.atlas` / `.png` 三件数量对不上，回放 spine 场景缺皮。
- **判断方法**（通用命令，对应 docs/16_人工抽检验收SOP.md:116 的勾选项）：

```powershell
$cg = "D:\UCGR_Work\unitycg\<游戏名>\cg"
"json=" + (Get-ChildItem $cg -Recurse -Filter *.json -File).Count +
" atlas=" + (Get-ChildItem $cg -Recurse -Filter *.atlas -File).Count +
" png=" + (Get-ChildItem $cg -Recurse -Filter *.png -File).Count
```

- **真实案例**：NTRaholic 图 86 张 + spine 附属 12 个（reports/人工抽检/预筛可疑.md:70）、LoveConfessions spine 附属 196 个（同文件:101）、BloodOfYidhra spine 220 + still 45（docs/15_游戏库验收_GitHub管理.md:287）——spine 款的 png 里混着图集，png 数 ≠ CG 张数，对数时先看 `cg-index.json` 的 `counts.cg`（docs/16_人工抽检验收SOP.md:48、:105）。
- **处理动作**：数量不一致记 `spine_mismatch`（docs/16_人工抽检验收SOP.md:193）；无 spine 的款直接勾过。

### 2.7 扩展名与实际格式不符（.png 其实是 JPEG）

- **现象**：图能看，但按扩展名解析的脚本报「文件头损坏」。
- **真实案例**：気息（上等）228/1521 张（reports/人工抽检/预筛可疑_rmmz.md:108）、Shitsuke-ai 759/1026 张（同文件:115）。
- **判断方法**（通用命令，按魔数核对前 4 字节：PNG = `89 50 4E 47`，JPEG = `FF D8 FF`）：

```powershell
Get-ChildItem "<图片目录>" -Recurse -Filter *.png -File |
  Where-Object { $b = [System.IO.File]::ReadAllBytes($_.FullName)[0..3];
                 $b[0] -ne 0x89 -or $b[1] -ne 0x50 } |
  Select-Object -First 20 FullName
```

- **处理动作**：预筛已改为**按内容取尺寸**并单独计 `misnamed`，不再误记损坏（tools/review-prescreen/README.md:59-60）；自写脚本时按内容嗅探而非扩展名。另有「内容全 0 的占位 png」：气息（上等）`712测试用图.png` 前 32 字节全 0，画廊显示「尺寸未知」（tools/review-gallery/README.md:231）。

## 3. 「命令报错」类

### 3.1 go build / go run 报找不到包或模块

- **现象**：`go: cannot find main module` 或包路径不存在。
- **判断与处理**：本仓库是**双模块**结构——根目录 `go.mod`（根模块）+ `desktop/go.mod`（GUI 模块），发布校验要求两者分别 `go build/vet/test` 全绿（docs/08_发布流程.md:55，docs/10_本地环境配置.md:8）。在根目录跑根模块、`cd desktop` 后跑 GUI（docs/12_0.4.0_验收报告.md:121）。Go 版本以 go.mod 为准，当前 `go 1.27.2`（go.mod:3）。
- **平台限制**：CLI（`cmd/ucgr`、`cmd/cgreplay`）与 GUI 依赖 `internal/platform/win32`，**只能在 Windows 构建**；`GOOS=linux` 下仅 `internal/`（除 win32）与 `tools/...` 可编译（docs/10_本地环境配置.md:9-10）。

### 3.2 CGO / gcc 报错（`cgo: C compiler "gcc" not found`）

- **现象**：构建时报 CGO 相关错误。
- **判断与处理**：先确认不是自己换依赖换出来的——本仓库 SQLite 用的是 **modernc.org/sqlite 纯 Go 实现**（go.mod:5，internal/catalog/catalog.go:22 `_ "modernc.org/sqlite"`），**不需要 CGO、不需要 gcc**。历史设计文档里提过 `mattn/go-sqlite3`（docs/01_需求规格说明书.md:140，那个才需要 CGO）；如果构建报 CGO 错，检查 go.mod 是否被改回了 mattn 系，恢复用 modernc.org/sqlite 即可。哈希用的是标准库 crypto/sha256（internal/hash/hash.go:3-4），同样无 CGO。

### 3.3 字体相关：注册 OTF 失败 / 文字变宋体

- **现象**：`--font-file` 传了 OTF 但观感不对或注册失败。
- **根因（实测）**：GDI `AddFontResourceExW` 注册 CFF/OTF **失败**（GDI 不支持 OTF/CFF），已退回系统 SimSun（reports/S3_单事件端到端spike_重返蓝鲸岛_2026-10-18.md:338；docs/05_流水线设计.md:60）。要忠实还原需改 GDI+ 的 `GdipPrivateAddFontFile` 路线（同 S3:338）。
- **判断与处理**：`ucgr play` 支持 `--font 名字` 与 `--font-file otf`（cmd/ucgr/main.go:108）；字体测试样本用环境变量 `UCGR_OTF` 指向真实 .otf 文件，未设置时对应测试跳过不报失败（docs/10_本地环境配置.md:15、:36）。

### 3.4 路径含空格 / 中文 / 日文 / 换行符

- **现象**：命令报 `syntax is incorrect` 或找不到文件。
- **判断与处理**：
  1. **所有路径参数都加引号**——本库游戏目录含中文、日文、空格甚至 `(` 结尾（如 `RA26037409(`，reports/人工抽检/预筛可疑_rmmz.md:94），文档里可复制的命令一律带引号（docs/16_人工抽检验收SOP.md:62-64）。
  2. **换行符坑（真实踩过）**：第 0 批 CLI 曾报 `syntax is incorrect`，复现后确认是**测试脚本的换行符 \r 混进了路径**，不是 CLI 缺陷（reports/第1批_RPG_Maker_扫描验证_2026-11-04.md:97）。从网页/文档复制长命令后先检查行尾。
  3. **PowerShell 多行命令**：续行用行尾反引号 `，文档示例见 docs/16_人工抽检验收SOP.md:76-78——复制时别把反引号弄丢或把下一行粘到同一行。

### 3.5 路径长度超 260

- **现象**：深层嵌套 + 日文目录名下读文件报错或漏文件。
- **背景（实测）**：游戏目录含日文名与深层嵌套（如 `（不赖）ideal-eves-room-_1.0.0`、`ゴブリン＆ソード…`）；**Go 程序统一用 `\\?\ `` 前缀兜底，PowerShell 脚本需开启长路径兼容**（docs/14_游戏库全量验收_执行计划.md:200）。
- **判断方法**（通用命令，找出超长路径）：

```powershell
Get-ChildItem "<游戏库根>" -Recurse -File |
  Where-Object FullName.Length -gt 250 |
  Sort-Object { $_.FullName.Length } -Descending |
  Select-Object -First 10 FullName, @{n="Len";e={ $_.FullName.Length }}
```

- **处理动作**：以管理员跑一次启用系统长路径（需重启生效）：

```powershell
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" -Name LongPathsEnabled -Value 1
```

  git 侧若克隆报路径过长：`git config --global core.longpaths true`。临时绕过可用 `\\?\E:\…` 前缀。

### 3.6 编码：PowerShell `` `n `` 与 UTF-8 输出乱码

- **现象 A**：拼出来的字符串里出现意外换行，或路径里带 `n 被吃掉。
- **处理**：PowerShell 双引号字符串里 `` `n `` 是换行转义——**路径一律用单引号**（`'E:\…\魔性少女'`），只有确实要换行时才用双引号 + `` `n ``。
- **现象 B**：控制台输出中文/日文乱码；脚本原文本身是 UTF-16LE / Shift-JIS。
- **判断与处理**：
  1. 先开 UTF-8 控制台：`[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`（或 `chcp 65001`）。rmmz 款文件名含日文是常态（`メイン3part4.png` 等，reports/人工抽检/预筛可疑_rmmz.md:1685-1687）。
  2. 库侧**不做猜测转码**：脚本原文按原始编码保存、编码信息由适配器记进 IR（docs/02_数据模型与包格式规范.md:172-174）；CP932/UTF-16 判别由适配器的 `decodeSegAuto` 实测可分（docs/04_引擎适配器接口规范.md:297）。
  3. 画廊导出的 CSV 是 **UTF-8 BOM**，Excel 直接打开不乱码（tools/review-gallery/README.md:137）；自写导出脚本也带 BOM。

### 3.7 文档里的子命令与实现对不上：`ucgr rescan` 不存在

- **现象**：照 docs/16_人工抽检验收SOP.md:157 的复现命令示例 `go run ./cmd/ucgr rescan "…"` 跑，报未知子命令。
- **判断与处理**：`cmd/ucgr` 实际子命令以 `cmd/ucgr/main.go:98-122` 的用法表为准：`scan / probe / refs / prune / ir / replay / play / events / decode / unpack / engines / audio`——**没有 rescan**。目录级复扫用 `ucgr events <解包目录>`（扫出原作事件表，main.go:115-117）或跑 library-audit；遇到文档命令先 `go run ./cmd/ucgr` 不带参数看 usage（main.go:161-162 的 `-h/--help` 也行）。

## 4. 「回放不对」类

### 4.1 IR 与素材根不匹配：回放渲染不出图 / 全部引用解析失败

- **现象**：`ucgr replay/play` 能跑但不出图，或报引用路径解析不到。
- **判断方法**：
  1. 确认 `--assets` 语义——rmmz 款 Ref 是**游戏根相对路径**（`www/img/pictures/x.png` 或 `img/pictures/x.png`），`--assets` 要指到**游戏根**（reports/第1批_RPG_Maker_扫描验证_2026-11-04.md:82-83）；SOP 命令则指到 `<游戏根>\www`（docs/16_人工抽检验收SOP.md:62-64）——**两种口径都有，以该款 IR 里 Ref 的形态为准**，先抽一条 Ref 看它相对哪个根：

```powershell
# 从 ir.json 里抽第一条 image 引用看路径形态（通用命令）
$ir = Get-Content "<ir.json>" -Raw | ConvertFrom-Json
$ir.assets | Select-Object -First 5 orig_path
```

  2. `--assets` 指错对象是高频坑：S3 spike 里 `--assets` 指向的是 **S2 裁剪产物（274 文件）而不是原树**，那条输入链才成立（reports/S3_单事件端到端spike_重返蓝鲸岛_2026-10-18.md:216）；回放全量演出时又要指回解包根/游戏根。
  3. 引用不到图记 `trace`（事件引用图缺失，docs/16_人工抽检验收SOP.md:154、:193）。
- **处理动作**：按 Ref 形态改 `--assets`；rmmz 双布局（`www/` 前缀 vs 根布局 `data/`）都已实测走通（reports/第1批_RPG_Maker_扫描验证_2026-11-04.md:87-90），别手工改 IR 里的路径。

### 4.2 事件编号对不上

- **现象**：GUI 里事件数和 `cg_count` 对不上；或事件 id 里的编号跟图片序号对不齐。
- **判断方法**：
  1. **先对口径**：rmmz 的 `cg_count` 实为**事件数，含对话事件**，不要按纯 CG 数要求它（docs/16_人工抽检验收SOP.md:104、:190）。
  2. **事件 id 形态**：rmmz 事件 id 是 `map:Map007.json:2:2#0`（地图事件）或 `common:237#0`（公共事件）——地图坐标/公共事件号与图片序号本来就不是一个体系（reports/第1批_RPG_Maker_扫描验证_2026-11-04.md:87-88）。
  3. **图片编号连续性**按文件名数字查跳号（docs/16_人工抽检验收SOP.md:139-142 原命令，rmmz 把路径换成 `img/pictures`）：

```powershell
Get-ChildItem "…\<图片目录>" -Recurse -Filter *.png |
  ForEach-Object { if ($_.BaseName -match '(\d+)') { [int]$Matches[1] } } |
  Sort-Object |
  ForEach-Object { $prev = -1 } { if ($_ -ne $prev + 1) { Write-Output "跳号: $prev -> $_" }; $prev = $_ }
```

  4. 真实序列断裂案例：Shitsuke-ai 533 处/2 个目录（reports/人工抽检/预筛可疑_rmmz.md:115）、女主角（大雷）2 处/1 个目录（同文件:1639）。缺族/断裂记 `number_gap`（docs/16_人工抽检验收SOP.md:154）。
- **处理动作**：数字对不上先查口径（事件数 vs 图数），再查跳号；跳号可能是「引擎素材被剔除」造成——预筛默认剔除 tilesets/characters 等引擎素材族（tools/review-prescreen/README.md:54-56），对数时用 `-keep-assets` 复核。

### 4.3 字体缺失导致对话文字不显示 / 显示成宋体

- **现象**：回放有画面有对话框，台词文字不出现或观感明显不对。
- **判断方法**：查该款 IR 的 `texts[].style.font_hint`（docs/03_IR规范.md:174）与游戏目录内的字体文件：

```powershell
Get-ChildItem "<游戏根>" -Recurse -Include *.otf,*.ttf,*.ttc -File |
  Select-Object FullName, Length
```

- **根因与处理**：渲染走 GDI 文字（`CreateFontW`+`DrawTextW`，reports/S3_单事件端到端spike_重返蓝鲸岛_2026-10-18.md:321）；游戏自带 OTF（如思源宋体）时 GDI 注册失败退 SimSun（同文件:338，docs/05_流水线设计.md:60）——文字「能显示但字体不对」是已知边界，忠实还原需 GDI+ 路线。文字排版整体是「近似」定位：`texts[].style` 提示 + 按引擎调优（docs/07_里程碑与验收标准.md:120）。测试环境字体样本用 `UCGR_OTF`（docs/10_本地环境配置.md:36）。

### 4.4 回放被黑屏守卫拦下 / 开场黑一片

- **现象**：打开事件提示「整段没有有效画面」，或 CG 预览图显示入场黑屏。
- **判断与处理**：守卫已是**多帧采样**——`OpenEvent` 内 5 帧守卫，三帧全黑才判 `ErrAllBlack`，单帧/两帧纯黑为 `Inconclusive` 不拦截（docs/12_0.4.0_验收报告.md:115、:120），且「单帧黑幕不再拦截会话」的修复已接线（commit 13fd591，见 git log 与 docs/12_0.4.0_验收报告.md:118）。开场黑属于**入场黑屏**：预览/封面已改为按时间轴采样避开入场段（commit 4634636，docs/12_0.4.0_验收报告.md:126-128；docs/11_v0.4.0_迭代计划.md:25-30）。仍被拦的事件先按 §2.3 排除「本来就是黑幕素材」再报问题款。

### 4.5 画廊只显示一部分图（显示 200/715）

- **现象**：rmmz 源目录款缩略图数远少于实际图数。
- **判断与处理**：自动发现给 rmmz 款 `max_images = 200`，按**等步长抽样**覆盖整个目录、不是只取前 200 张（tools/review-gallery/README.md:224）；标题条会显示「显示 200/715」chip。要全量看某款：删掉清单里该款的 `max_images`、加 `-max-per-game 0` 重跑（同文件:226）：

```powershell
go run ./tools/review-gallery -max-per-game 0
```
