## 一、批次定义（排期 §7）

> 新建 `internal/adapter/renpy/`：.rpa 索引解析 + .rpy 语句提取。

实际实现按事件库直连落地：

- `internal/adapter/renpy/`（新包）：
  - `rpa.go`：RPA-3.0 归档索引解析 + 按名读取。**实测兼容两种变体**：
    标准（文件名 hex+XOR 密钥）与明文变体（文件名原样、offset/size XOR 密钥，
    见 Supower-Re / xxxFiles）；索引支持 zlib 压缩（`78 9c` 魔数）；
    pickle 解析器覆盖协议 2/5 子集（FRAME/MEMOIZE 自增索引/BINGET('h')/TUPLE1-3 等）。
  - `rpy.go`：明文 `.rpy` 语句提取（label / image 定义 / scene / show / hide /
    台词 / with / pause），跳过 python 块与分支结构。
  - `renpy.go`：game 目录探测（含整合包套壳、大写 `Game`、双层嵌套）、
    扫描（每含图片演出的 label 一个事件）、IR 台本构建（图层+台词+转场）。
- 图像三级解析：`image` 显式定义 → 明文文件（images/ 目录自动命名）→ .rpa 条目；
  外加**后缀模糊匹配**兜底（千千阙歌：文件在 `images/backgrounds/office reception day.jpg`，
  脚本写 `show office reception day`）。
- .rpa 资源播放时**按需解包**到 `game/.ucgr-cache/`（不改写游戏文件）。
- 接入点：`library.ScanWith` 分派、`desktop` 检测/回放分派、
  `ucgr events --engine renpy` 与 `ucgr play --engine renpy --script <.rpy> --label <label>`。

## 四、过程中发现与修掉的问题

1. **pickle 操作码表两处想当然**：SETITEMS 是 `'u'`(0x75) 不是 0x76；
   实测归档（协议 5）里 `h\x03` 是 **BINGET**（配合 MEMOIZE 自增索引复用
   空前缀对象），不是 BINPUT——字节流证据定案（memo 序号与 `h\x03` 取回
   第 4 次 MEMOIZE 的空 bytes 完全自洽）。
2. **RPA 数值编码两变体**：明文名归档的 offset/size 才 XOR 密钥
   （`0x42424271 ^ 0x42424242 = 51`，魔数 PNG 验证），标准归档数值原样。
3. **图像名后缀匹配**：Ren'Py 引擎本身允许脚本省略子目录名，补了兜底键。
4. **panic 修复**：`ToLower` 长度漂移导致切片越界（千千阙歌踩中）。
5. zlib 压缩索引（部分打包器行为）。
