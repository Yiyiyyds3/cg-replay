## 1. CatSystem2 剧本格式（实测）

- 剧本是 `.cst`：`CatScene` 魔数 + zlib；解压后条目为 `01 <type> <bytes> 00`，
  type `0x20`=对白 / `0x21`=角色名 / `0x30`=脚本命令（提取器复用前人
  `extract_cst_text4.decompress_cst / raw_entries`）。
- **资源引用语法**（甜蜜女友2/灰色的乐园实测）：

| 命令 | 语义 | 例 |
|---|---|---|
| `bg/cg/fg/eg/fw/pl/mpl <槽位> <名>` | 图层图片（名后可跟 `,位置参数…`） | `bg 1 bg05Lwb`、`eg 2 eff_kiss_anm` |
| `pcm <名>` | 语音 | `pcm BB_03_rei_30H_001` |
| `se <buf> <名>` | 音效 | `se 1 se_a2_train_passing_1` |
| `movie <名>` | 影片 | `movie ed_cit` |
| `call <名>` | 子剧本调用（非资产） | `call e_rei19MN_01` |

- `.cst` 分布在 `原始归档解包/scene/`（基础）+ `原始归档解包/update01/`（汉化覆盖层），两棵都扫（取并集，保守）。

## 2. 三个 CS2 专属匹配规则（都踩过坑）

1. **多层 HG3 组匹配**：解包工具把多图层 HG3 展开成 `Tama01f_0001..0052.hg3`（一层一文件），
   剧本裸名 `Tama01f` 指向**整组**——少一层都渲染不出来。
   实现 `build_group_index`（`<name>_<序号>` 归组），未命中从 81 → 5。
2. **语音 take 后缀**：PE 的引用是 `A_19_sayuki_ex01_022_1`（带 take），文件名是
   `A_19_sayuki_ex01_022.ogg`（不带）→ `pcm` 引用同时登记「去 `_<数字>` 后缀」变体。
   **修前 PE 的语音几乎全没匹配上（④ 2.63 GB），修后 4.13 GB**。
3. **E-mote 硬边界**：`.psb/.psz/.lpb` 按 FINAL §4.4/§11 **不复刻、可整块删除** →
   从 ④ 剥出单独报告（8 款合计 57011 个文件 / 0.65 GB；PE/2/2+/+ 四款有，灰色系无）。

## 3. 池口径

池 = `原始归档解包`（HG3 原样/fes/psz…）∪ `音频`（语音/BGM/音效）∪ `视频`；
**排除 `图片` 目录**——那是前人 HG3→PNG 的派生副本（如 `图片/bg01/bg01La_0000.png`），
库按「原样入库」只留 HG3。故池体积 < M0 ③ 口径（③ 含派生副本），比值为「唯一数据中需保留的比例」。
