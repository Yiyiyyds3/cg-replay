## 6. S3 暴露的问题（本次 spike 当日的原始记录）

> ⚠️ 本节保留 spike 当日原貌。其中**第 2、5、6 条的表述经复核有误**，第 1、3、4、7 条已修/已进库 —— 逐条更正与复测见 **§9**。

1. **`[iscript]…[endscript]` 的 JS 代码被当成台词** —— `replay` 输出的时间轴开头是 `{`、`// システムボタンを使っていて…`、`kag.fore.layers[i].visible = false;` 等 JS 行，全部计入了 `texts`（2359 条里含大量非台词）。**根因**：`kirikiri` 的脚本解析器未跳过 `[iscript]` 块。
2. **`♪path` 标记混进台词** —— 如「一派颇具南国风味的晴朗天气…… ♪raw/data/sound/click.ogg」，文本行里带了 `♪` 资源标记，未剥离。
3. **IR 的 `image_show` 不带位置/透明度** —— 实测 op 形如
   `{"t_ms":0,"op":"image_show","target":"imagebase","params":{"ref":"kaigan01_bg"}}`，
   没有 `left/top/z/opacity`，**因此无法从 IR 还原画面**（本次合成图是绕过 IR、直接解析脚本标签做的）。这与 codebuddy 文档步骤 5「位置参数引用提取」的预期不符【未验证：也许位置保存在别处】。
4. **`layers` 是「最终态猜测」，重复且失真** —— 8 个图层只有 3 个不同资产（`kuro.jpg` 出现 4 次），且与时间轴首个 `image_show`（`kaigan01_bg`）不一致（`kuro.jpg` 应是脚本后段的内容）。
5. **整个剧本 = 1 个事件** —— 5423 行 / 2744 个 op 全部落在同一个事件里，「CG show→hide 自动切分」在 KAG 这种 `[image layer=...]` 风格下没有真正切开（该脚本没有 `[hide]` 标签）。S3 需要的「一个 CG 事件」粒度目前做不到。
6. **时间轴没有时间** —— 所有 `t_ms` 都是 0，`transitions` 254 条也没有参与时间轴计算 → 现状是「按文本顺序的清单」，不是「可播放演出」。
7. **JPEG 被单字节 0xA4 掩码（重要）** —— `kaigan01_bg.jpg` 原始头 `5b7c5b44`，XOR 0xA4 后 = `ffd8ffe0`（JPEG JFIF），尾 `5b7d` XOR 0xA4 = `ffd9`；全树扫描：**`.jpg` 1185 个全部掩码、`.png` 962 个全部未掩码**。`System.Drawing`（GDI+）直接读掩码 JPG 报 `Out of memory`。→ 与 P0 报告里「海市蜃楼之馆：单字节 XOR 0xA4」是同一手法。**决策表触发：S1「发现加密/混淆 → 暂停，先解决解密」**，本次用自写 Python 解掩码绕过。
8. **识别回归（已修）** —— `ucgr refs <该树>` 起初报 `未能识别引擎`：`.ks` 位于 `raw\data\scenario\`（路径深度 4），而 `kirikiri.Identify` 的 `dirProbeMaxDepth` 是 3。**已改为 5**（`internal/adapter/kirikiri/kirikiri.go`，未提交）。

### 13.1 为什么又做一轮（对交付形态的修正）

§3~§12 做的 `internal/replay` 是「按时刻采样合成帧 / GIF」——**用户明确否定了这种形态**，原话：

> 「不对啊，这不是我想要的效果，我需要的是完整的cg事件回放（bgm,文本,cg）这个完整的cg回复应当是游戏本身就自带的，我只是把各个游戏的cg完整cg回访摘出来，使用cg-replay统一管理罢了，而不是这种把cg轮番播放的类型」

⇒ 交付形态改为**窗口实时播放器**：把游戏自己那套演出（立绘/背景按时间轴淡入淡出 + 转场 + 抖动 + 对话框原文的点击节奏）原样重放，cg-replay 只负责「把各作的完整演出摘出来统一管理」。采样帧/GIF 降级为**离线出图工具**（保留，用于验证与人工比对）。

用户拍板的三条（question 工具已确认）：① 交付 = 窗口实时播放器，不做导出视频；② 文本推进 = 自动为主 + 可手动（尊重 `[wait]`/`[wt]`，原作等点击处按字数估时自动翻页，可暂停/加速/手动推进）；③ 事件粒度先不定，先把引擎与播放器做出来。

### 13.3 播放语义（KAG 忠实度取舍）

- **双缓冲**：`backlay` 把 fore 复制到 back；`page=back` 的层命令改 back，`trans` 启动时快照 fore、在 `time` 毫秒内 `display = blend(fore→back)`，结束 `fore=back`；同层换图时画两层互补不透明度做真交叉淡入。**本作 `[image]` 带 `page=back` 274 处 / `page=fore` 5 处，`[position]` 不带 page 全在 load.ks（读盘画面）⇒ KAG 默认 page=fore**（已按此实现；此前 §9 里「未建模双缓冲」的缺口就此关闭）。
- **顺序阻塞**：`[wait]`/`[wt]`/`[quake]`/文本点击点是阻塞点（`[wt]` = 等当前转场走完）；`[image]`/`[layopt]`/`[position]`/`[backlay]`/音视频是非阻塞。**不按 TMs 排序调度**——因为台词之间的原作点击等待无法用时间戳表达，必须顺序执行。
- **文本**：`[台詞 name=X]` 按 namae.ks 宏展开的等价效果生成「名字牌(message1) + 对话框(message0, frame=win3.png) + 名字行」；`[l]`=点击等待、`[r]`=换行、`[cm]/[np]/[per]`=清页、`[er]`=清当前层；自动时长 = `0.8s + 75ms×字数`，clamp [0.8s, 6s]（**播放器策略，非脚本保真**；本作无角色语音可依）。
- **对话框真相**（namae.ks + Config.tjs 复核）：message0 几何 `(56,700,1456,476)`、框图 `fgimage\win3.png`（1495×473，**图片自身含左上角名字牌 + 下方主对话框**，原尺寸贴）、文字区 margin `t110/l50/r50/b60`；message1 名字牌 `(90,646,400,500)`、`opacity=0`（= frameOpacity，不画底色）。`Config.tjs`：画布 1600×1200、字号 48、行间 12、白字黑阴影、`[position]` 的 `opacity` 是 **frameOpacity** 而非图层 alpha（图像层的 `opacity` 仍是图层 alpha 0~255）。

### 14.1 为什么又做一轮（对交付形态的第二次修正）

第四轮交付的是「命令行 + 手输路径 + 两步走（`ucgr ir` 出 IR，再 `ucgr play` 播放）」，事件粒度是「一个脚本 = 一个事件」。用户明确否定：

> 我需要的应用端应该是.exe直接运行的那种，你现在说的这个方式极不方便测试也不方便使用，并且各个cg事件应该按照原本的游戏的分割方式进行分割，每个CG都是单独的事件，而不是把所有的cg整合到一起播放

本轮就解决这两件事：**① 交付形态 = 双击即用的 GUI `.exe`**；**② 事件粒度 = 按原作自己的分割方式（每个 CG 一个独立事件）**。

### 14.2 原作自己的分割方式（实测依据）

本作把 CG 鉴赏写成三层结构：

| 文件 | 作用 | 实测要点 |
| --- | --- | --- |
| `raw\data\scenario\cgrai.ks` … `cgrai6.ks` | CG 鉴赏列表，6 页 × 16 格 | 每格 `[sysbutton graphic="cg017" name="cg017" page=fore top=… left=… call storage="cgrai00.ks"; target=*cg17]`；解锁判定 `[if exp="sf.cg017 == 1"]`；网格 4 列（left 164/494/824/1154）× 4 行（top 162/382/602/822） |
| `raw\data\scenario\cgrai00.ks` | 每格点开后的实际演出（1633 行） | 每个 `*cgNN` 段 = 一个 CG 事件 |
| `raw\data\scenario\01kuukou.ks` … `76utyu.ks` | 主线剧本 | 每个编号脚本 = 一个场景事件（共 79 个） |

一个 CG 事件的原文样板（`*cg01`）：

```
*cg01
[clickskip enabled=false]
[sysbutton_erase page=back]
[image layer=base storage="kuukou01" page=back visible=false]
[trans method=crossfade vague=1 time=200][wt]
[clickskip enabled=true]
[l]
[call storage="cgrai.ks"; target=*modoru]
[s]
```

⇒ 一个 CG 事件 = **1~N 个「页」**（每页：换一张图 → 一次 `crossfade 200ms` → 一次 `[l]` 点击等待），看完回画廊。实测多页例：`*cg04`（kuruma1→kuruma3，2 页）、`*cg08`（kaijyou1→…→kaijyou8，8 页）、`*cg10`（akirado1→akirado3，3 页）、`*cg14`（be1→be4，4 页）。

**这 96 个 `cg001`…`cg096` 槽位就是「原作自己的 CG 分割方式」**，本轮直接拿它当事件单位（不再自己发明切法）。`ucgr events` 扫出来的结果：**CG 事件 96 个 · 场景事件 79 个**。

### 14.4 顺带修掉的忠实度问题：base 层的 `visible` 无意义

CG 事件每页都是 `[image layer=base storage="X" page=back visible=false]` + `[trans][wt]`。按字面执行会把图**隐藏掉** ⇒ 整屏全黑（离线出图实测第一版就是这个症状）。但原作画廊里 CG 是正常显示的 ⇒ **base/背景层的可见性在 KAG 里无意义（始终绘制）**。

修正（`build_show.go`）：目标层是 base/stage/back/background（或 `layer=0`）时忽略 `visible=false`，仍发 `layer_show` 且把属性改成 `visible=true`（防止播放器再按属性隐藏）。全树统计：`[image|img|ev|evset … visible=false|0]` 共 544 处，其中背景层 210 处（这些原先都会误隐藏）、`layer=0` 13 处、其余层 321 处（真隐藏，保持原语义）。

### 14.6 本轮仍存缺口（对 §13.6 的更新）

1. **事件粒度已定**（96 个 CG 事件 + 79 个场景事件）；多页 CG 的第 2 页起需要「点击等待」——GUI 里空格/回车/点画面手动推进，或开「自动推进」（2500 ms）。**长场景事件（如 `71kaigan01.ks`，自动播放 > 1 小时）仍是一整块**，暂未再切段落。
2. 字体、音频、`universal` 转场、`[img]` 裁剪读法四项与 §13.6 相同（本轮未动）。
3. GUI 侧小项：窗口固定尺寸；列表不做缩略图预览；无「按 CG 名搜索」输入框。
