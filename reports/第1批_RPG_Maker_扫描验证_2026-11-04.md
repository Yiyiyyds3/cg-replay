## 3. 3 款失败的根因

**统一根因：图片由插件/脚本驱动，静态事件命令里没有图片名。**

| 游戏（评价） | code 231 Show Picture | code 355 Script | 检测到的插件函数 |
|---|---:|---:|---|
| 呪いの鎧 v3.0.1（夯） | 0 | 大量 | `this.cgLoad`、`this.picsChange2`、`this.picsDel`、`this.picsOut`、`$w.startZm` |
| 詛咒铠甲2（夯） | 1 | 大量 | `this.picsChange2NM`、`$w.setInfo`、`$wb.removeNpcs`、`this.cgLoad`、`$w.setW` |
| wuxian（未评级） | 2 | 大量 | `$utils.shakeScreen`、`$utils.setupTime`、`$battleManager.initConfig` 等 |

图片名由插件运行时状态决定，静态 `Map*.json` / `CommonEvents.json` 里没有 `Show Picture` 的图片名 → `Segments` 切不出演出段 → `Refs=0`。

### 已排除的两个误判

- **不是解密问题**：这 3 款的 `.rpgmvp` 加密图片由 `decode.DecodeImage` 实测可正常解码（`3g.rpgmvp` 1024×578、`background.rpgmvp` 1136×640，`pictureLarge=true`），`System.json` 的 `encryptionKey` 也齐全。
- **不是路径问题**：`FindDataDir` / `ImageDirs` / `LocatePicture` 对这 3 款都返回正确目录（`www/data`、`www/img`）。

## 7. 首帧渲染验收（2026-11-04 补）

rmmz 是「事件库直连」架构（不走五方法的 `prune.Pool`），验收链路按实际架构执行：
`rmmz.Scan` → 选图片最多的事件 → `rmmz.BuildShow` → 包成 `ir.IR` JSON → `ucgr play <ir.json> --assets <游戏根> --shot --at` 离线出帧。
`Ref` 是游戏根相对路径（`www/img/pictures/x.png` / `img/pictures/x.png`），`replay.GameLoader` 第一候选即命中；加密 `.rpgmvp` 由 `decode.DecodeImage` 解出。

| 游戏（引擎·评价） | 扫描 | 选中的事件 | 渲染 |
|---|---|---|---|
| 冒险者莉扎西亚（MV·一般，`www/` 布局） | 137 事件 / 753 图 / 3340 文 | `map:Map007.json:2:2#0`：22 图 / 66 文 → 296 条 show 指令 | ✅ t=0/3s/10s 出帧，11 层合成正常 |
| NTRエロトラップダンジョン（MZ·上等，根布局 `data/`） | 97 事件 / 421 图 / 9364 文 | `common:237#0`：20 图 / 321 文 → 618 条 show 指令 | ✅ t=0/8s 出帧，立绘 + 效果层清晰无错位 |

**已确认**：MV/MZ 两种目录布局、明文 PNG 与加密 `.rpgmvp`、地图事件与公共事件两类来源，全部走通「扫描 → 台本 → IR → 渲染首帧」。
**已知保真度边界**：MV 差分立绘（同一部位多个表情/姿势变体）在静态提取下会同层半透明叠加，画面出现轻微重影——原作靠运行时条件切换显示，静态 IR 无该状态。属既定「不追 100% 还原」范围。
