补充事实（都在逐款 JSON 里，可复核）：

- **`engine_detected` 五款全为空**。原因不是审计器没调：`library.DetectEngine` 的通用竞聘只覆盖已注册适配器（kirikiri/scn/artemis/bgi/catsystem2/nscript/nexas/nitro）。库里 **没有 NW.js、Unity、Godot、Unreal 的 Identify 实现**（`internal/adapter/unitycg`、`internal/adapter/rmmz` 也都没有 `adapter.Register`，不参与竞聘）。所以本批 5 款的引擎归属**只能靠 TSV 的 engine_guess 兜底映射**。这条已如实记在 verdict 的 `engine_resolved`（`rmmz` / `godot` / `unreal` / `unity` / 空）。
- **「按评价」目录层是 Junction（重解析点）**。例：`按评价\大雷\女主角（大雷）` → `20260424\RPG\大雷\女主角（大雷）`。审计器把实体目录记在 `real_path`。`filepath.WalkDir` 与 `filepath.EvalSymlinks` 都不认这种重解析点（前者把根当非目录、一个子项都不遍历），审计器改用 `os.ReadDir` 递归 + `os.Readlink` 解析。**只读**：只是换路径形式访问同一个目录，未改动/删除/移动/解包落盘任何原游戏目录内容。
- 大雷款 `top_entries=22`，`asset_dirs` = `www/img/pictures(715张图)`、`www/img/system(18张图)`、`www/img/tilesets(31张图)`、`www/img/titles2(5张图)` 等；`cover_valid=true`，取图 `www/img/titles1/title.png`，`cover_non_black=0.998`。
- 5 款 `can_unpack` 全为 `false`：Godot `.pck` / Unreal / 未知 NW.js / Unity 目录都不在 `unpack.Preview` 的识别范围内（`kind=unknown, unsupported=true`，原始理由：`这个目录里没找到可识别的归档（也没找到已解包结构 raw/data/scenario）`）。

## 五、如实声明（不做无证据的通过）

1. **本层是只读批量审计**：全部操作都是 `os.Stat` / `os.ReadDir` / `library.ScanWith` / `unpack.Preview` / 读图解码，**没有**解包落盘、**没有**改动/删除/移动/解包到任何原游戏目录；产物只写 `reports/audit/`。
2. **没有做第二层真机 GUI 回放**：因此「鼠标点击可推进」「语音出声」「预览首帧非黑屏」这三条，本批**只有代码路径证据**（第 7 条的 panic/静默失败、第 3 条的封面图非近黑），**没有实机证据**。清单里按 ⬜ 记「未验」，不记通过。
3. **`skip` 不等于「不支持这游戏」**：3 款的 skip 全部是「main 分支上 `library.ScanWith` 没有该引擎的 `ScanXxx` 分派」，或引擎都认不出来（`拉` 款）。这是能力缺口，不是游戏本身坏。
4. **`fail` 是一条真实报错**：`The Blood of Yidhra` 的 Unity 扫描缺 `cg-index.json`，报错原文已完整进 `errors`（未截断、未改写）。
5. **数字口径**：本批共 5 款（大雷 1 / 很牢 1 / 牢 2 / 拉 1），与 docs/14 ② 的 13 分组 117 条一致；剩余 = 117 − 5 = **112**。

## 六、工具交付与用法

```powershell
# 全库审计（默认读 reports/游戏库验收_任务清单.tsv，写 reports/audit）
go run ./cmd/library-audit

# 只跑指定分组（本批）
go run ./cmd/library-audit -group "大雷,很牢,牢,拉"

# 常用可选参数
#   -tsv <路径>       任务清单
#   -root <库根>      默认 E:\Personal_entertainment\game\ero\egame\_游戏库\按评价
#   -out <目录>       默认 reports/audit
#   -timeout 15m      单款上限；超时 verdict=skip / reason=timeout，不再耗着
#   -batch batch-1    本批 verdict 数组文件名（<out>/<batch>.json）
```

判定规则（与代码注释一致）：

- 路径不存在 → `fail` / `path_missing`；不是目录 → `fail` / `path_not_dir`。
- 引擎在 main 无 `ScanXxx` 分派 → `skip` / `engine_unsupported_in_main`，errors 里写明支持清单，**不进入扫描**（docs/14 ⑥ 不死磕）。
- 扫描 panic → 文本原样进 `errors`，`fail` / `scan_panic`（若可解包则 `partial`）。
- 扫描报错 → 再 `unpack.Preview`（只读）：可解包 `partial` / `scan_error_can_unpack`，否则 `fail` / `scan_error`。
- 事件数为 0 → 同样走预览：可解包 `partial` / `no_events_can_unpack`，否则 `fail` / `no_events`。
- 事件数 > 0 且无 error → `pass` / `events>0`。
- 单款超过 `-timeout` → `skip` / `timeout`。

单测：`cmd/library-audit/main_test.go`，覆盖 TSV 解析（制表符 / 中文 / 单引号游戏名 / BOM / 注释行 / 列数不足报错）、引擎推断映射、verdict 判定（无入口→skip、events>0→pass、报错原文进 errors、可解包→partial、零事件→fail/partial、panic→fail、path_missing）、超时分支、summary 计数、封面候选名不误判（`Recovery1` / `discover` 不算封面）。全部不依赖真实游戏目录。
