## 1. Artemis 剧本格式（实测，比前两个引擎都简单）

`.ast` 是**明文 Lua 表**（无需解密，前人已解出）：

```
astver = 2.0
ast = {
["0001_00012"]={
{"msgoff"},
{"bg",file="black",path=":bg/",sync=0},              -- 背景
{"bg",file="effects_13_s",id=2,lv=2,movie=1,...},    -- 动画层
{"bgm",file="bgm29"},                                -- BGM
{"vo",file="man_hir_00001",ch="hir"},                -- 语音
{"evset",file="ev_cut_001_00",set="ev_cut_001",...}, -- 事件 CG
{"excall",file="00_プロローグ_1"},                   -- 剧本间调用（非资产）
...
```

- 资源引用 = 命令里的 `file="..."`；资源命令词表：`vo/bg/fg/fgf/fgact/se/bgm/evset/movie/excall/cg`。
- 路径别名（`:bg/` `:cg/` `:fg/xx/z1/` `:ani/` `:sys/`）是分类提示；**个别命令把别名写进 file 里**
  （`file=":ani/kiss"`）→ 解析时剥掉 `:别名/` 前缀（实测甜蜜女友3 有此形态，不剥会整批漏匹配）。
- 图片在 pfs 内就是 **PNG/JPG（原格式）**，提取后位于 `图片/<卷>/image/...`；语音在 `音频/<卷>/sound/...`；
  影片在 `视频/<卷>/...`。
- `.ast` 分布在 `文本/<卷>/script/`（たねつみ 83 个；三款共约 300 个）。

## 2. 池口径

池 = 整树，排除：前人派生文本（`剧本_对话_*`、`资源调度/`）、清单/说明（`.md/.txt`）、
脚本自身（`.ast`）、松散 `.pfs` 卷文件。**E-mote（.psb/.psz/.lpb）进池但按硬边界从 ④ 剥出**
（与 CS2 口径一致，可删量才看得见）。池 ≈ M0 ③ 口径（甜蜜女友3：池 19.39 vs ③ 19.48 GB）。

## 3. 踩过与修过的坑

| # | 坑 | 修法 |
|---|---|---|
| 1 | `excall/selback` 的 file= 是**剧本名**（`00_プロローグ_1`），不是资产 → 虚占未命中、还经动态保留误捞文件 | 用 `.ast`  basename 集合识别，归入「剧本引用」（DR-25 剧本全留） |
| 2 | `file=":ani/kiss"` 把路径别名写进了 file 值 → 整批漏匹配 | 剥 `^:[A-Za-z0-9_/]*/` 前缀 |
| 3 | E-mote 最初被排除出**池** → 4.78 GB 可删量被隐藏 | 改为进池、从 ④ 剥出（与 CS2 一致） |
| 4 | 基础卷与汉化卷（`sakuranotoki_chs.pfs.021`）同名文件 → basename 歧义匹配失败 | 新增 `match_all`：同名文件全部算命中（同资产多版本） |
