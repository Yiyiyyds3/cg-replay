# UCGR 差异化定位 · 市面对比做减法（V3 修订）

依据：reports/research/ 4 方向调研（40+ 项目，2026-11-21 全部验证）+ 本次 V3 开工实测。

## 一、市面格局一句话
解包层是红海（GARbro 3.4k★ 停更、arc_unpacker 归档、QuickBMS 脚本生态 2900+ 格式）；库管理层有 KoiPage/Playnite 等，但都止步于「启动」；媒体库（Hydrus/Immich）有去重标签但没有游戏语义；**「事件→CG 序列回放」与「A/B 对比模式」在全部 40+ 项目中不存在**——这是 UCGR 独占的生态位。

## 二、做减法的结论（什么不做）
1. 不做通用解包浏览器（GARbro 形态）——UCGR 的解包只服务事件回放链路
2. 不做多引擎格式竞赛——覆盖主人库实际遇到的 12+ 引擎即可
3. 不做 pairwise 去重关系网（Hydrus 自认失败）——「事件=组」天然绕开
4. 不做 Postgres/向量库/ML 服务/多用户/移动端/云同步——SQLite + 单机足够（Stash/TagStudio 双证）
5. 不做封包/写回（arc_unpacker 作者论证投入产出比极低）
6. 不做主题生态/插件运行时/商店分发——留适配器注册表一个扩展点

## 三、特点与过人之处（什么必须做）
1. **事件=组的语义层**：CG 按「原作自己的事件」组织（画廊槽位 + 场景 + 章节），不做自由标签海——这是全部竞品没有的
2. **有效性过滤（本次 V3 新增）**：无有效帧的 CG 事件不出库（validate.go：图帧存在性 + 特殊事件特征 + 空索引安全阀），GUI 打开就能播
3. **文本/音频一并验收（本次 V3 新增）**：textdump 按脚本导出台词（kirikiri AST 优先 + rmmz 401 拼接 + artemis），音频计数入对账——竞品没有「入库即验收」
4. **加密图别名判定**：E 盘源目录直接扫（.rpgmvp/.png_ 存在即有效）——不必先解包全库
5. **对账闭环**：每游戏 cg_kept/dropped/audio/text/source_images 一张表（acceptance_v3），主人人工测试有底册
6. **对比模式（调研发现的空白）**：列入 P2 路线，作为 GUI 差异化招牌
