- 全程只读：所有操作是 `os.Stat` / `os.ReadDir` / `Readlink` / `library.ScanWith` / `unpack.Preview` / 读图解码，**没有**解包落盘、**没有**改动/删除/移动原游戏目录任何内容；产物只写 `reports/audit/`。

## 五、进度口径（三项 + 两项）

用户要求的口径：**累计已验收 X / 卡点跳过 Y / 剩余 Z（共 117）**，另列**失败待修 F**、**进行中 P**。

| 项 | 算式 | 值 |
|---|---|---|
| 累计已验收 X | 批1 pass 1 + 批2 pass 5 | **6** |
| 累计卡点跳过 Y | 批1 skip 3 + 批2 skip 5 | **8** |
| 剩余 Z（未跑） | 117 − 已跑 21 | **96** |
| 失败待修 F | 批1 fail 1 + 批2 fail 4 | **5** |
| 进行中 P（partial） | 批1 partial 0 + 批2 partial 2 | **2** |

校验：`6 + 8 + 5 + 2 = 21`（已跑）；`21 + 96 = 117`；`6 + 8 + 96 + 5 + 2 = 117` ✅ —— 与 `summary-batch1.json`（total 5 / pass 1 / partial 0 / fail 1 / skip 3）和 `summary.json`（total 16 / pass 5 / partial 2 / fail 4 / skip 5）逐项对得上。

剩余 96 款的批次划分（docs/14 ③）：批 3 未评级 44 / 批 4 中等 16 / 批 5 中上+不赖 10 / 批 6 夯 19 / 批 7 创意+上等 7 = 96 ✅。

> 口径提醒：「已验收」在本层 = 批量层 pass，不等于 7 条清单全过。真要转成 `status/已验收` 标签前，第 4/5/6 条必须补第二层真机证据。

## 六、标签拆分（fail / skip 不再混为一谈）

`.github/workflows/bootstrap-game-library.yml` 本轮同步段已改成 5 个状态标签，`fail` 与 `skip` 彻底分开：

| verdict（JSON 里的值） | 标签 | 语义 |
|---|---|---|
| `pass` / `passed` / `ok` / `verified` / `已验收` | `status/已验收`（0e8a16） | 7 条清单全过 |
| `fail` / `failed` / `blocked` / `待修` | **`status/待修`（c5def5，新增）** | 扫描报错/缺产物，需补代码或先导出 |
| `skip` / `skipped` / `卡点` / `卡点跳过` | `status/卡点跳过`（b60205） | 卡点未解，15 分钟超时跳过 |
| `partial` / `partial_pass` / `部分通过` / `进行中` | `status/进行中`（1d76db） | 正在跑，未出结论 |
| （其它/认不出） | `status/进行中` | 兜底 |

remove-label 循环已加入 `status/待修`，保证一个 issue 只留一个状态标签（幂等）。**本批 4 款 fail 会落到 `status/待修`，5 款 skip 落到 `status/卡点跳过`，2 款 partial 落到 `status/进行中`** —— 换标签前这 4+5=9 款会全挤在 `status/卡点跳过` 一列，看板上根本分不清「要我写代码」和「引擎还没接」。
