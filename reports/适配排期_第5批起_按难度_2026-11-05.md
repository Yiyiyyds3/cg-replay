## 1. 难度怎么定

四个维度，任一变难即升档：

1. **格式公开度**：公开索引 / 明文 → 私有二进制 → 加密 / 编译字节码 → 需逆向。
2. **是否要写新解析器**：能复用现有适配器（事件库直连）最省；新归档解析次之；私有语义最贵。
3. **是否要新工具链**：现成工具（unrpyc）、自己升级探针（probe_xp3 → 解包器）、IDA/Ghidra 逆向。
4. **解出后能否直接接现有链路**：xp3 解完直接复用第 0 批 KiriKiri；rpyc 反编译完直接复用 renpy。

难度档：`★` 格式公开且几乎复用 → `★★★★★` 需逆向、单款收益。

### 各批动作与验收

**第 5 批 · Electron asar**

1. 读 asar 头（4B 头长 + Pickle 序列化的 JSON 目录），按目录表切出文件；`app.asar` 通常含 `dist/` 明文资源。
2. 解出的 `dist/assets/{images,video}` 直接走 `internal/adapter/media`（与 Touch Simulation 同形），无需新适配器。
3. 验收：2 款都能 `ucgr events --engine media` 出事件、各渲 1 张首帧；`go test ./...` 全绿。

**第 6 批 · WOLF-RPG**

1. 实现 wolf 归档（`.wolf`）条目表解析，落盘到临时解包目录（不改动原游戏，遵守 README 硬约束）。
2. 按 `Data/*.mps` 等事件脚本切分演出；若语义解析成本过高，先降级为「散图/影片事件」走 media 兜底。
3. 验收：999 从 6 个兜底事件提升到正式 CG 事件；莱特娜出事件且首帧可渲。

**第 7 批 · Godot .pck**

1. 先复核 CSV 里另 2 款 Godot 的真实目录（库里目前只定位到 1 个 `.pck`）。
2. pck 头 + 文件表解析；Godot 导入资源（`.stex`/`.tex`）需转 PNG，或复用 `decode.DecodeImage` 扩展。
3. 验收：至少 1 款出事件 + 首帧渲染；转不出的资源诚实报 unknown，不伪造。

**第 8 批 · 工具链补齐**

1. `probe_xp3.py` 目前只列条目，补「按条目导出到目录」，对齐第 0 批 `raw/` 结构（scenario / fgimage / evimage …）。
2. 导出后魔剣士レーヴェ直接跑既有 KiriKiri 链路（`ScanWith` → kirikiri），验证零代码改动可用。
3. SRPG Studio 单独评估 `data.dts`；若资料不足，记录形态后转暂缓，不硬做。
4. 验收：魔剣士出事件并渲首帧；xp3 解包器有单测覆盖路径穿越与坏条目。

**第 9 批 · enc 加密**

1. 静态定位 `libcocos2d.dll` 里 "enc" 魔数引用与解密函数，确定算法与密钥来源。
2. 解出后先验证 PNG 魔数、project.json 明文，再决定走 media 还是 rmmz 语义（该作套了 RPG Maker MV 参数层）。
3. 验收：至少 1 张图可解码；若逆向成本超预算，保留结论并转「点名才做」。
