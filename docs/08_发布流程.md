# 08 · 发布流程（Releases）

> **红线（不可越过）**：本文件只描述「怎么发布」，**不代表已发布**。
> 任何 Release 上传 / tag 推送，必须同时满足：
> 1. **用户已完整测试通过**（用户明确说「可以发了」）；
> 2. **用户明确许可本次发布**（含版本号与产物）。
>
> 未经许可擅自 `gh release create` 或 `git push origin v*` 属于越权操作，
> 会把未验证的构建推到公开渠道、且难以撤回（tag 一旦推送就长期存在）。

## 1. 版本号规则：按功能完善度

不按日期、不按提交数，按「用户能拿它做什么」分档。判定标准是**可验证的能力**，
不是「代码写完了」。

| 版本 | 功能完善度（判定标准） | 状态 |
| :--- | :--- | :--- |
| 0.1.x | 单事件回放内核（CLI，逐帧回归口径） | 历史 |
| 0.2.0 | 单游戏桌面 GUI：事件库 + 回放 + GIF/MP4 导出 + 索引骨架 | 历史 |
| **0.3.0** | **多游戏库 MVP**：多游戏登记/切换 + 跨游戏卡片墙 + 收藏三级（游戏/事件/角色，各带评分备注）+ 导出任务中心（异步/进度/取消）+ NSIS 安装包 + 数据目录每用户化 + 72h 冷归档 | **当前** |
| 0.4.0 | **第二款真实游戏可入库**：引擎约定配置化落地（换游戏只改 `ucgr-convention.json`）+ 多作混用回归通过 | 计划 |
| 1.0.0 | 功能完备且稳定：多作长跑无崩溃、真实语料回归全绿、代码签名发布 | 计划 |

小版本（0.3.1）只放**修复**；功能变化一律进下一个中版本。

## 2. 构建产物

```bash
# 前端产物（可选，wails build 会自己 build）
cd desktop/frontend && npm run build

# 生产 exe
cd desktop && wails build -s

# NSIS 安装包（每用户安装，无 UAC；需本机装 NSIS/makensis）
#   makensis 在 C:\Program Files (x86)\NSIS（winget 装的话当前终端 PATH 看不到，要显式加）
cd desktop && wails build -nsis -installscope user -s
```

产物：

| 文件 | 大小（约） | 说明 |
| :--- | :--- | :--- |
| `desktop/build/bin/cgreplay-ui.exe` | 16.9 MB | 免安装绿色版（数据写在 exe 同目录） |
| `desktop/build/bin/cgreplay-ui-amd64-installer.exe` | 8.3 MB | NSIS 安装包（每用户装到 `%LOCALAPPDATA%\Programs\…`） |

**构建禁忌**：
- 不要用 `wails build -clean`（会清空 `build/bin`；数据已迁到 `%LOCALAPPDATA%\cgreplay-ui`，
  但仍会删掉构建产物）。
- 数据目录在 `%LOCALAPPDATA%\cgreplay-ui`（第三十四轮起），卸载安装包**不会删**它
  （用户数据不随程序消失）。

## 3. 发布前检查清单

- [ ] `go build ./... && go vet ./... && go test ./...`（根 + `desktop/` 两个模块）全绿
- [ ] `cd desktop/frontend && npm run build` 无 TS 报错
- [ ] `wails build -s` 与 `wails build -nsis -installscope user -s` 均成功
- [ ] 产物 exe 无头启动 12s 存活（WebView2 环境创建成功、无 Go panic）
- [ ] 静默安装冒烟：`installer.exe /S`（Git Bash 下需 `MSYS_NO_PATHCONV=1`）→ 安装
      → 快捷方式生成 → 启动存活 → 数据落在 `%LOCALAPPDATA%\cgreplay-ui` → 卸载干净
- [ ] **用户在本机完整测试通过**（用户明确确认）
- [ ] 版本号按上表判定，写入 `desktop/wails.json` 的 `productVersion` 与
      `desktop/main.go` 的 `Version()` 字符串
- [ ] 计算 SHA256 校验和

```bash
cd desktop/build/bin
sha256sum cgreplay-ui-amd64-installer.exe > SHA256SUMS
```

## 4. 发布动作（**等用户许可后才执行**）

```bash
# 1) 打 tag（先本地 commit 干净）
git tag -a v0.3.0 -m "cg-replay 0.3.0：多游戏库 MVP"
git push origin v0.3.0

# 2) 建 Release 并挂产物
gh release create v0.3.0 \
  desktop/build/bin/cgreplay-ui-amd64-installer.exe \
  desktop/build/bin/SHA256SUMS \
  --title "cg-replay 0.3.0 · 多游戏库 MVP" \
  --notes-file docs/09_发布说明_0.3.0.md
```

发布说明模板见 `docs/09_发布说明_0.3.0.md`（随版本更新）。

## 5. 代码签名（未做，需证书）

当前安装包**未签名** → 首次运行会被 Windows SmartScreen 拦截（「未知发布者」），
用户需点「更多信息 → 仍要运行」。要做正式分发需：

1. 购买代码签名证书（OV/EV）；
2. `signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 <file>`；
3. 在 NSIS 模板里加 `#!finalize 'signtool …'`（模板已预留该行，注释状态）。

自签证书只对本机有效，不解决 SmartScreen 拦截。
