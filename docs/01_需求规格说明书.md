## 0. 一句话目标

把已解包的 galgame 资源**裁剪**成"只够重演 CG 事件"的最小集合，装进**一套自研回放应用**，从而在**完整重温 CG 演出**的同时**大幅降低硬盘占用**。

---

## 1. 范围

### 1.1 要（In Scope）

- CG 图片 + 事件视频
- BGM **全部保留**
- 背景 / 立绘 / 差分 / 语音 —— **只保留 CG 演出所需部分**
- 剧本对白保留（演出中显示台词）
- 回放档位 = **C3 完整演出**：背景 → 立绘 → CG → 文本 → 语音 → BGM → 转场

### 1.2 不要（Out of Scope）

| 不做项 | 原因 |
|---|---|
| "大一统引擎"（通用游戏引擎模拟器） | 只做 IR 回放；过度设计是明令禁忌 |
| 有损转码 | 画质必须无损 |
| 全量预转 PNG | PNG 常比原格式更大，且掩膜/图层有转丢风险；统一按需解码 |
| E-mote 动态立绘复刻 | 需官方 SDK，硬边界不可复刻，只能标注缺失 |
| 实时联网 / 多端同步 | 纯本地单机；网盘只是半自动冷归档通道 |
| 游戏本体（exe/dll）管理 | 本体按游戏个人定夺；回灌只还原资源，不保证可运行 |

## 2. 术语表

| 术语 | 定义 |
|---|---|
| CG 事件 | 一段可独立重演的演出单元：静帧 CG、事件视频、或含立绘对话的场景演出 |
| IR | 统一演出中间表示（Intermediate Representation），回放器唯一输入 |
| 精简集 | 由 IR 反推出的资源引用并集（整游戏并集 + 事件引用表） |
| 包（package） | 一个游戏一个包，`.ucgpkg` 目录，自包含可独立打开 |
| 中心库 | 跨游戏索引（SQLite），仅索引不含资源，损坏可由各包重建 |
| fidelity | 保真度分级：`generic` / `tuned` / `exclusive`，每游戏一个 |
| 旁挂 / 接管 | per-game 模式开关：旁挂=原归档保留，库只作副本；接管=库为准，原归档可走待删区删除 |
| 待删区 | 删除暂存区，保留期 **72 小时（3 天）**，到期才真删 |
| 回灌 | 从包把资源写回原归档结构（仅资源，不含本体） |
| 冷归档 | 把包/资产上传网盘并记录上传状态与回下载路径；上传前加密 |
| 误裁 | 把 CG 演出需要的资源裁掉了；由三层检测兜底 |

## 3. 已冻结决策全表（§3 七轮 Drill 结论，原样收录）

> 以下 37 条为上游文档第 3 节全部决策，**编号为本文档新增的追溯号**，内容未改一字。标记「待实测」的项须在 M0 阶段用数据复核。

### Round 1 · 目标与范围

| # | 决策项 | 结论 |
|---|---|---|
| DR-1 | CG 范围 | 图片 + 视频 |
| DR-2 | 资源类型 | 纳入 BGM / 语音 / 背景图 / 立绘 |

### Round 2 · 使用场景与部署

| # | 决策项 | 结论 |
|---|---|---|
| DR-6 | 是否继续玩 | 部分玩、部分不玩 → 需要 **per-game 模式开关** |
| DR-7 | 部署 | 单人单机；未来扩展到个人平板 / 手机 |

| DR-9 | 网络 | 纯本地；但**需要网盘冷归档**（记录上传状态与回下载路径） |
| DR-10 | 后台任务 | 允许常驻，但**必须有进度、可暂停、可随时退出** |

### Round 3 · 存储与去重

| # | 决策项 | 结论 |
|---|---|---|
| DR-11 | 画质 | **必须无损**（接受不转码） |
| DR-12 | 盘布局 | 跨盘（本体与库不同盘）；删本体后可同盘 |
| DR-13 | 去重 | 同一份数据只存一次（内容寻址） |
| DR-14 | 模式默认 | 默认**接管**；保留**回灌**能力 |

### Round 4 · 来源、摄入与"用不上"的判定

| # | 决策项 | 结论 |
|---|---|---|
| DR-15 | 回放档位 | **C3-精简**：脚本解析 → 引用裁剪 → 轻量指令回放（非重写引擎） |
| DR-16 | 非 CG 资源 | BGM 全保留；背景/立绘/差分/语音**只保留 CG 演出所需** |
| DR-17 | 游戏本体 | **按游戏个人定夺**：删 / 留 / 传网盘兜底 |
| DR-18 | 格式策略 | **原样入库 + 按需解码**（不全量转 PNG） |
| DR-19 | 归档策略 | 倾向 **b**：只存精简集（但执行 a→b 两段删除，见 05 文档阶段 F） |
| DR-20 | 扩展性 | 接受逐个引擎硬啃，**须为未来新引擎预留余量** |
| DR-21 | 优先引擎 | 先做**素材最多**的那个 → 数据结论：**KiriKiri** |
| DR-22 | 特例需求 | 对特别喜欢的游戏，**单独做到该游戏全部 CG 演出效果**（fidelity=`tuned`） |

### Round 5 · 精简集、索引与保真度契约

| # | 决策项 | 结论 |
|---|---|---|
| DR-23 | 包形态 | **一个游戏一个包** |
| DR-24 | 索引存放 | **中心库汇总 + 包内嵌小索引**（资源只有一份，重复的仅 KB~MB 级索引） |
| DR-25 | 脚本原文 | **保存**（文本或二进制原始字节；压缩后极小，且是 IR 与裁剪的依据） |
| DR-26 | 裁剪粒度 | **整游戏并集 + 事件引用表**（不做事件级最小集） |

## 4. 用户与场景

**用户画像**：单人单机的 galgame 收藏重温党；硬盘紧张；部分游戏还会玩，部分只留 CG 回忆。

| 场景 | 描述 | 覆盖 FR |
|---|---|---|
| S1 重温 CG | 打开客户端 → 选游戏 → 逐事件重演完整演出（背景/立绘/CG/文本/语音/BGM/转场） | FR-06 |
| S2 省空间 | 摄入 47 款解包目录 → 裁剪入库 → 原归档走 a→b 两段删除 → 出降幅报告 | FR-01~04、FR-14 |
| S3 还会玩的游戏 | per-game 保持旁挂或保留原归档，随时回灌，本体不删 | FR-15、FR-16 |
| S4 检索回忆 | 按台词全文搜到某句 → 跳到对应事件回放 | FR-08 |
| S5 导出分享 | 把某事件导出静帧/GIF/视频 | FR-10 |
| S6 冷归档 | 生成待上传清单+校验码 → 人工上传 → 回填记录 | FR-17 |

## 5. 功能需求（FR）

> 每条 FR 标注了验收要点；字段级定义在配套文档。

### FR-01 引擎识别与摄入
- 输入：解包目录（或原归档文件）
- 流程：引擎识别（04 文档 `identify`）→ 归档解析（`parse_archive`）→ 完整性侧录生成
- 验收：47 款现有目录 100% 有归属（识别成功或明确标记"未知引擎"）；识别禁止瞎猜（不确定返回 None）

### FR-02 脚本解析与 IR 生成
- 输入：脚本原文（DR-25 保存原始字节）
- 流程：`parse_script` → `build_IR` → IR schema 校验（03 文档）
- 验收：生成的 IR 100% 通过 schema 校验；解析不出的指令按保守保留规则处理（04 文档 §6）

### FR-03 引用裁剪
- 输入：IR
- 输出：事件引用表 `refs.json` + 整游戏资源并集
- 验收：误裁检测第一层——IR 引用的资源 100% 存在于并集；未识别指令保守保留

### FR-04 打包（一游戏一包）
- 产出：`.ucgpkg` 目录（02 文档 §2）
- 验收：包可脱离中心库独立打开；中心库删除后可由各包完整重建

### FR-05 中心库索引
- SQLite：游戏 / 事件 / 资产 / 台词 FTS / 角色 / 收藏 / 重温清单 / 冷归档 / 待删区 / 任务
- 验收：跨游戏检索（DR-28 全部维度）可用；208 万文件量级下查询 < 1s

### FR-06 CG 回放（C3 完整演出）
- 背景 → 立绘 → CG → 文本 → 语音 → BGM → 转场，按 IR 时间轴确定性重演
- 验收：抽样事件人工比对原版演出（误裁检测第三层）；缺资源必须**可见告警**，不得静默失败

### FR-07 调试模式（DR-29）
- 逐句 / 逐图层：暂停、下一句、跳句、显示图层
- 验收：可定位到单条 IR 指令；图层树可显隐、可看资源信息（hash/原路径）

### FR-08 检索（DR-28）
- 游戏分组 / 角色 / 引擎 / 收藏 / **台词全文搜索**（SQLite FTS5）
- 验收：台词搜索命中可直达事件并定位到句

### FR-09 收藏与重温清单（DR-31）
- 收藏 / 评分（1~5）/ 备注 / 重温清单（playlist，可排序）
- 验收：收藏跨重启持久化；清单可按序连续回放

### FR-10 导出（DR-30）
- 静帧（PNG）/ GIF / 视频
- 验收：导出物是回放过程的派生产物，**不触碰库内原资产**；导出失败不影响库

### FR-11 后台任务（DR-10、DR-32）
- 扫描 / 哈希 / 缩略图 / 完整性校验 / 摄入 / 冷归档导出 / 回灌测试
- 验收：每个任务都有进度条、**可暂停**、**可随时退出**、退出后可断点续跑

### FR-12 完整性校验（DR-33、DR-34）
- 入库与回灌均校验 BLAKE3 哈希清单
- 验收：哈希不符 → 明确报错并定位文件，禁止静默跳过

### FR-13 误裁检测与告警（DR-35）
- 三层：①IR 引用必全（自动）②回放缺资源必须告警（UI 可见）③抽样人工比对（流程）
- 验收：三层各有产出物（校验报告 / 告警 UI / 人工比对记录）

### FR-14 待删区与删除保护（DR-36）
- 任何删除先进待删区，**72 小时**后才真删
- 验收：待删区内可恢复、可提前手动销毁（二次确认）；到期自动真删并记录

### FR-15 per-game 模式开关（DR-6、DR-14）
- `旁挂` / `接管` 两态，默认接管
- 验收：对"还会玩"的游戏必须保留原归档；切换模式有明确后果提示

### FR-16 回灌（DR-14、DR-37）
- 从包把资源写回原归档目录结构，哈希校验通过
- 验收："还会玩"的游戏做**回灌往返测试**（回灌 → 校验 → 记录结果）；明示"回灌 ≠ 可运行"（本体删了游戏仍起不来）

### FR-17 冷归档（DR-9）
- 生成待上传清单 + 校验码 → 人工/第三方工具上传 → 回填记录
- 验收：字段完整（content_hash / 云端服务 / 云端路径或标识 / 上传时间 / 云端校验码 / 回下载方式，02 文档 §4）；**上传前加密**；不锁死单一网盘

### FR-18 保真度管理（DR-22、DR-27）
- 每游戏一个 `fidelity`（generic/tuned/exclusive）；tuned = 该引擎转场/特效/排版逐个补齐
- 验收：fidelity 记录在包与中心库；tuned 升级是适配器侧工作，不改核心

### FR-19 E-mote 标注
- 遇到 E-mote 动态立绘数据：**不复刻**，在游戏与事件级标注"此项不可复刻"
- 验收：标注在 UI 可见；对应资源（.psb/.psz/.lpb）在裁剪时可整块排除并计入降幅报告

## 6. 非功能需求（NFR）

| # | 类别 | 需求 |
|---|---|---|
| NFR-1 | 规模 | 2,081,409 文件量级：扫描/哈希/缩略图必须可暂停、可退出、可断点续跑（DR-10、DR-32） |
| NFR-2 | 性能 | 哈希用 BLAKE3（高频大文件）；SQLite 查询 < 1s；缩略图 WebP 且 LRU 缓存 |
| NFR-3 | 无损 | 库内资产为原始格式（TLG/HG3/SGCG/OGG…），**禁止有损转码**，显示时按需解码 |
| NFR-4 | 自包含 | 每个包可独立打开（DR-23、DR-24） |
| NFR-5 | 索引预算 | 包内嵌索引必须是 KB~MB 级，**不得复制资源** |
| NFR-6 | 安全 | 冷归档上传前加密（防扫描/和谐）；口令本地保管 |
| NFR-7 | 可移植 | 内核与界面分离：摄入/去重/索引/归档跟踪为独立 core，桌面壳只是它的一个前端；未来移动端**换壳不换核心** |
| NFR-8 | 数据安全 | 删除必须过待删区；完整性侧录 JSON 弥补"删归档"不可逆 |

## 7. 约束与硬边界

1. **E-mote 动态立绘不复刻**（需官方 SDK）；遇到则标注"此项不可复刻"。
2. **回灌 ≠ 可运行**：回灌只还原资源，本体（exe/dll）删了游戏仍起不来。
3. **不做通用引擎模拟器**：回放器永远只吃 IR。
4. **M0 清点前不得承诺具体降幅**；真实数字由 M0 清点 + 单引擎试跑给出。
5. **未实现的转场 id → 自动回退 L0 近似**（淡入淡出），保证"不崩、能看"。
6. **裁剪安全原则**：解析器认不出的指令 → 保守保留其可能引用的资源，并标记"未识别"（宁多勿缺）。

## 8. 风险摘要

详见 07 文档 §6 风险台账。摘要：E-mote 不可复刻 / 转场 L0 只能近似 / 文字排版需近似 / 删归档不可逆（靠完整性侧录+待删区+per-game 开关兜底）/ 回灌≠可运行 / 网盘半自动且需加密 / 工程量随引擎数线性增长 / 208 万文件规模是重活。
