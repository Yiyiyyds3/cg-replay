## 3. 全局质量门禁（任何阶段都适用）

| 门禁 | 内容 | 依据 |
|---|---|---|
| **G1 哈希闭环** | 入库与回灌均校验 BLAKE3；不符即报错定位，禁止静默跳过 | DR-33 |
| **G2 完整性侧录** | manifest.json 全量条目 + 哈希，删归档前的唯一溯源 | DR-34 |
| **G3 误裁检测三层** | ①IR 引用必全 ②缺资源必须告警 ③抽样人工比对 | DR-35 |
| **G4 待删区** | 一切删除过待删区 + 72h 保留期 | DR-36 |
| **G5 回灌往返** | "还会玩"的游戏必须做往返测试；明示"回灌 ≠ 可运行" | DR-37 |

## 4. 度量指标

| 指标 | 口径 | 出处 |
|---|---|---|
| 单游戏裁剪率 | 剔除量 ÷ 解包产物体积 | manifest.json totals + M0 |
| 库总占用 | Σ 包 assets_bytes（硬链接去重后物理占用） | 中心库统计 |
| 节省总量 | M0 v2b − 当前库占用 | 降幅报告 |
| 解析覆盖率 | 成功解析游戏数 ÷ 尝试数 | 摄入报告 |
| unrecognized 密度 | unrecognized 数 ÷ 事件数 | 中心库 |
| 缺资源告警数 | 回放器告警计数 | 日志 |

> ❗ 降幅类指标在 M0 + P0 试跑完成前**一律不得对外引用**（禁忌第 2 条）。

## 7. 架构变更单流程（§3 冻结决策的保护机制）

1. 变更申请人填写：变更项（DR 编号）、理由、影响面（文档/schema/代码）、回滚方案。
2. 影响面必须覆盖：01 决策表 / 02 数据模型 / 03 IR / 04 适配器 / 05 流水线 / 06 客户端 / schema 三份 / 07 里程碑。
3. 评审通过后同步更新全部受影响文档，并在本文档留变更记录。
4. 未经变更单，实现方不得放宽硬约束（含本文档 §8 禁忌）。

## 8. 禁忌复核清单（上游 §14，逐条可勾）

- [ ] 未擅自删除任何原资源；一切删除经过待删区 + 保留期或明确 per-game 开关
- [ ] 未在 M0 清点前承诺具体降幅
- [ ] 未做通用引擎模拟器；回放器只吃 IR
- [ ] 未做任何有损转码
- [ ] 冷归档未锁死单一网盘
- [ ] 包内嵌索引未变成资源冗余（KB~MB 级预算有强制检查）
