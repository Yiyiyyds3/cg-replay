## 1. 三层数据模型总览

```
┌────────────────────────────────────────────────────────┐
│ 包（package） 一个游戏一个 .ucgpkg 目录，自包含可独立打开      │
│   IR.json / refs.json / scripts/ / manifest.json /        │
│   hashes.txt / assets/ / thumbs/ / index/                 │
├────────────────────────────────────────────────────────┤
│ 中心库（SQLite） 仅索引，不含资源，损坏可由各包重建            │
│   games / events / assets / asset_packages / text_lines    │
│   （FTS）/ characters / favorites / playlists /            │
│   asset_cold / pending_delete / jobs / unrecognized        │
├────────────────────────────────────────────────────────┤
│ 冷归档（网盘侧） 由 asset_cold 表跟踪，上传前加密              │
└────────────────────────────────────────────────────────┘
```

**不变量**：

1. 资源物理上只存一份（内容寻址 + 硬链接去重），但**每个包都能独立打开**。
2. 中心库只存索引，删掉中心库可由各包重建（FR-04）。
3. 包内嵌索引 ≤ MB 级，**绝不复制资源**（NFR-5）。
4. 哈希算法统一 **BLAKE3**（hex 小写）。

## 2. 包格式（.ucgpkg）

### 2.1 目录布局

```
<library>/packages/<game_id>.ucgpkg/
├── package.json          # 包元数据（schema：package.schema.json）
├── IR.json               # 演出描述（规范见 03；schema：ir.schema.json）
├── refs.json             # 事件引用表（schema：refs.schema.json）
├── scripts/              # 脚本原文（原始字节，保留原归档相对路径）
│   └── <原始相对路径…>
├── manifest.json         # 完整性侧录：原归档完整条目清单 + 哈希（DR-34）
├── hashes.txt            # 内容哈希清单（DR-33）
├── assets/               # 精简资源，内容寻址命名
│   └── <h[:2]>/<h>       # 前 2 字符分桶，避免单目录数十万文件
├── thumbs/               # WebP 缩略图（派生物，可随时重建，不进 hashes.txt）
│   └── <h[:2]>/<h>.webp
└── index/                # 包内嵌小索引（KB~MB 级，供包独立打开/检索）
    ├── events.json       # 事件摘要（id/kind/title/缩略图 hash/起止）
    ├── text.jsonl        # 本游戏台词（每行一条，供包内全文检索）
    └── characters.json   # 角色列表
```

> `game_id` 命名规则：由游戏标题转写的 ASCII slug；重名时追加 8 位短哈希。一经生成**永不更改**（中心库、包目录、冷归档记录均以它为外键）。

### 2.2 package.json（字段级定义）

```json
{
  "format_version": "1.0",
  "game_id": "string，必填，game_id 命名规则",
  "title": "string，必填，展示用标题",
  "original_title": "string，可空，原文标题",
  "engine_id": "string，必填，如 kirikiri / artemis / catsystem2 / bgi / nscripter / unity_il2cpp / fvp / baldr / unknown",
  "engine_version": "string，可空，适配器识别出的引擎版本",
  "brand": "string，可空，厂商",
  "release_date": "string，可空，YYYY-MM-DD",
  "fidelity": "generic | tuned | exclusive，必填，默认 generic（DR-22/DR-27）",
  "hash_algo": "blake3，必填，固定值",
  "core_version": "string，必填，生成该包的内核版本",
  "has_emote": "boolean，必填，是否含 E-mote 动态立绘（不可复刻项）",
  "created_at": "ISO 8601，必填",
  "updated_at": "ISO 8601，必填",
  "source": {
    "archive_path": "string，可空，原归档（或解包目录）来源路径",
    "archive_entries": "int，可空，原归档条目总数",
    "archive_bytes": "int，可空，原归档总字节",
    "unpacked_bytes": "int，可空，解包产物总字节（M0 口径）"
  },
  "stats": {
    "events": "int，必填，事件总数",
    "scripts": "int，必填，入库脚本文件数",
    "assets": "int，必填，并集资源数",
    "asset_bytes": "int，必填，并集资源字节",
    "text_lines": "int，必填，台词条数",
    "unrecognized": "int，必填，未识别指令数"
  }
}
```

### 2.3 refs.json（事件引用表）

```json
{
  "format_version": "1.0",
  "game_id": "string",
  "hash_algo": "blake3",
  "events": {
    "<event_id>": [
      {
        "hash": "string，BLAKE3 hex",
        "role": "background | stand | cg | voice | bgm | se | movie | text_asset | unrecognized",
        "orig_path": "string，原归档内相对路径（溯源用）"
      }
    ]
  },
  "union": [
    { "hash": "string", "orig_path": "string", "role": "string" }
  ]
}
```

**规则**：

- `events` 是**逐事件**的引用表（FR-03 产出）；`union` 是整游戏并集（DR-26：整游戏并集 + 事件引用表，不做事件级最小集）。
- 并集中的每一项都必须能在 `assets/` 找到；缺一项即摄入失败（误裁检测第一层）。
- `role=unrecognized` 的条目来自保守保留（04 文档 §6），`orig_path` 必须为真实存在于原归档的路径。

### 2.4 manifest.json（完整性侧录，DR-34）

记录**原归档完整条目清单 + 哈希**，用于弥补"删归档"的不可逆：

```json
{
  "format_version": "1.0",
  "source_archive": "string，原归档标识（路径或归档文件名）",
  "hash_algo": "blake3",
  "entries": [
    {
      "path": "string，原归档内相对路径",
      "size": "int",
      "hash": "string，BLAKE3 hex",
      "in_package": "boolean，是否进了精简集"
    }
  ],
  "totals": {
    "entries": "int",
    "bytes": "int",
    "in_package": "int",
    "dropped": "int",
    "dropped_bytes": "int"
  }
}
```

**规则**：

- 全量条目，一条不漏——这是"删归档"后唯一的溯源依据。
- `dropped_bytes` 即本游戏本次裁剪**理论剔除量**，是降幅报告的数据源之一（真实降幅仍以 M0 四类体积口径为准，07 文档 §5）。
- 摄入期若原归档已不可读（例如先吃了别人的包），`manifest.json` 可从既有侧录继承，并在 `package.json.notes` 标注。

### 2.5 hashes.txt（内容哈希清单，DR-33）

每行一条，按相对路径排序，空格分隔：

```
<blake3_hex>  <relpath>  <size_bytes>
```

**覆盖范围**：`IR.json`、`refs.json`、`scripts/**`、`assets/**`。
**不覆盖**：`hashes.txt` 自身、`thumbs/**`（派生物，可随时重建）。
**用途**：入库校验、回灌校验、完整性侧录的包内闭环（FR-12）。

### 2.6 scripts/（脚本原文，DR-25）

- 原始字节**原样保存**，不做任何转码/解码/重编码。
- 保留原归档内的相对路径结构，便于与 `manifest.json` 对账。
- 文本脚本按原始编码保存（如 UTF-16LE / Shift-JIS），编码信息由适配器在 IR 元数据中记录，core 不做猜测。

### 2.7 assets/（内容寻址，DR-13）

- 命名 = BLAKE3(文件内容) hex；同包内不重复。
- 目录分桶：`assets/<hash前2字符>/<hash>`，防止单目录文件过多（Windows/NTFS 均受益）。
- **跨包去重**：新摄入的包若发现 hash 已存在于另一包 → 摄入完成后由「跨包去重整理」任务把后写入的副本替换为 **NTFS 硬链接**（同一份数据只存一份，且各包仍自包含可独立打开）。`asset_packages` 表记录每个 hash 的全部落点。
- 硬链接不可用时（跨卷/文件系统不支持）退化为保留副本并在中心库记录 `dedup=failed`，供人工决定。

### 2.8 thumbs/ 与 index/（索引预算，NFR-5）

- `thumbs/`：WebP，最长边 ≤ 512px，由后台任务生成（可暂停/退出/重建）。
- `index/`：events 摘要 + 台词 + 角色，**总量必须 ≤ 数 MB**；入库任务强制检查，超限即报错（防止"内嵌索引"退化成"资源冗余"——禁忌第 6 条）。

## 3. 中心库（SQLite）Schema

> 单文件数据库：`<library>/library.db`。仅索引，不含资源；删除后可由各包 `package.json + IR.json + refs.json + index/` 完整重建。

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;

-- 元信息
CREATE TABLE meta (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
); -- schema_version / library_id / created_at / core_version

-- 游戏（DR-4：按游戏分组）
CREATE TABLE games (
  game_id        TEXT PRIMARY KEY,
  title          TEXT NOT NULL,
  original_title TEXT,
  engine_id      TEXT NOT NULL,
  engine_version TEXT,
  brand          TEXT,
  release_date   TEXT,
  package_path   TEXT NOT NULL,            -- .ucgpkg 目录
  fidelity       TEXT NOT NULL DEFAULT 'generic'
                 CHECK (fidelity IN ('generic','tuned','exclusive')),
  mode           TEXT NOT NULL DEFAULT 'takeover'
                 CHECK (mode IN ('sidecar','takeover')),   -- DR-14：默认接管
  archive_path   TEXT,                     -- 原归档/解包目录路径
  keep_archive   INTEGER NOT NULL DEFAULT 0,               -- DR-6：还会玩则置 1
  event_count    INTEGER NOT NULL DEFAULT 0,
  asset_count    INTEGER NOT NULL DEFAULT 0,
  asset_bytes    INTEGER NOT NULL DEFAULT 0,
  source_bytes   INTEGER,                  -- M0 四类体积合计（对账用）
  has_emote      INTEGER NOT NULL DEFAULT 0,               -- FR-19
  notes          TEXT,
  created_at     TEXT NOT NULL,
  updated_at     TEXT NOT NULL
);

-- 事件（一个 CG 演出单元）
CREATE TABLE events (
  game_id          TEXT NOT NULL REFERENCES games(game_id) ON DELETE CASCADE,
  event_id         TEXT NOT NULL,
  kind             TEXT NOT NULL
                    CHECK (kind IN ('still_cg','event_video','scene','other')),
  title            TEXT,
  ord              INTEGER NOT NULL,       -- 游戏内顺序
  start_ms         INTEGER,
  end_ms           INTEGER,
  thumb_hash       TEXT,                   -- 指向 assets/（事件封面）
  has_unrecognized INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (game_id, event_id)
);
CREATE INDEX idx_events_kind ON events(game_id, kind);

-- 资产全局登记（内容寻址，DR-13）
CREATE TABLE assets (
  content_hash  TEXT PRIMARY KEY,          -- BLAKE3 hex
  size_bytes    INTEGER NOT NULL,
  kind          TEXT NOT NULL
                CHECK (kind IN ('image','voice','bgm','se','movie','script','other')),
  codec         TEXT,                      -- tlg/hg3/sgcg/png/jpg/ogg/wav/mpeg/...
  width         INTEGER,
  height        INTEGER,
  duration_ms   INTEGER,
  first_package TEXT NOT NULL,
  created_at    TEXT NOT NULL
);

-- 资产落点（hash ↔ 包，多对多；支撑硬链接去重与跨包检索）
CREATE TABLE asset_packages (
  content_hash TEXT NOT NULL REFERENCES assets(content_hash) ON DELETE CASCADE,
  game_id      TEXT NOT NULL,
  rel_path     TEXT NOT NULL,              -- 包内相对路径
  PRIMARY KEY (content_hash, game_id)
);

-- 冷归档（DR-9；字段集合同上游 §5.3）
CREATE TABLE asset_cold (
  content_hash    TEXT PRIMARY KEY REFERENCES assets(content_hash) ON DELETE CASCADE,
  cloud_service   TEXT NOT NULL,           -- 网盘服务名（不锁死单一服务）
  cloud_path      TEXT NOT NULL,           -- 云端路径或标识
  uploaded_at     TEXT,
  cloud_checksum  TEXT,                    -- 云端校验码
  download_method TEXT,                    -- 回下载方式
  encrypted       INTEGER NOT NULL DEFAULT 1,   -- 上传前加密（§6）
  key_hint        TEXT                     -- 口令提示（不存口令本身）
);

-- 台词（DR-3：CG 页展示台词）+ 全文检索（DR-28）
CREATE TABLE text_lines (
  line_id  INTEGER PRIMARY KEY AUTOINCREMENT,
  game_id  TEXT NOT NULL,
  event_id TEXT NOT NULL,
  t_ms     INTEGER,
  speaker  TEXT,
  text     TEXT NOT NULL
);
CREATE VIRTUAL TABLE text_lines_fts USING fts5(
  text, speaker,
  content = 'text_lines',
  content_rowid = 'line_id'
);

-- 角色（DR-28 检索维度之一）
CREATE TABLE characters (
  game_id TEXT NOT NULL REFERENCES games(game_id) ON DELETE CASCADE,
  name    TEXT NOT NULL,
  alias   TEXT,
  PRIMARY KEY (game_id, name)
);

-- 收藏体系（DR-31）
CREATE TABLE favorites (
  fav_id     INTEGER PRIMARY KEY AUTOINCREMENT,
  item_type  TEXT NOT NULL CHECK (item_type IN ('game','event','character')),
  game_id    TEXT NOT NULL,
  item_id    TEXT NOT NULL,
  rating     INTEGER CHECK (rating BETWEEN 1 AND 5),
  note       TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE (item_type, game_id, item_id)
);

-- 重温清单（DR-31）
CREATE TABLE playlists (
  playlist_id INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE TABLE playlist_items (
  playlist_id INTEGER NOT NULL REFERENCES playlists(playlist_id) ON DELETE CASCADE,
  ord         INTEGER NOT NULL,
  game_id     TEXT NOT NULL,
  event_id    TEXT NOT NULL,
  PRIMARY KEY (playlist_id, ord)
);

-- 待删区（DR-36：3 天保留期）
CREATE TABLE pending_delete (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  path        TEXT NOT NULL,
  size_bytes  INTEGER NOT NULL DEFAULT 0,
  reason      TEXT NOT NULL
              CHECK (reason IN ('b_delete','takeover','manual','dedup')),
  game_id     TEXT,
  created_at  TEXT NOT NULL,
  purge_after TEXT NOT NULL,               -- created_at + 72h
  status      TEXT NOT NULL DEFAULT 'pending'
              CHECK (status IN ('pending','purged','restored'))
);
CREATE INDEX idx_pending_purge ON pending_delete(status, purge_after);

-- 后台任务（DR-10：有进度、可暂停、可随时退出）
CREATE TABLE jobs (
  job_id         INTEGER PRIMARY KEY AUTOINCREMENT,
  kind           TEXT NOT NULL
                 CHECK (kind IN ('scan','hash','thumb','verify','ingest',
                                 'cold_export','roundtrip','dedup')),
  status         TEXT NOT NULL
                 CHECK (status IN ('queued','running','paused','done','failed','cancelled')),
  progress_done  INTEGER NOT NULL DEFAULT 0,
  progress_total INTEGER NOT NULL DEFAULT 0,
  checkpoint     TEXT,                     -- 断点续跑游标（JSON）
  payload        TEXT,                     -- 任务参数（JSON）
  error          TEXT,
  created_at     TEXT NOT NULL,
  updated_at     TEXT NOT NULL
);

-- 未识别指令登记（裁剪安全原则：宁多勿缺）
CREATE TABLE unrecognized (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  game_id     TEXT NOT NULL,
  event_id    TEXT,
  node_path   TEXT,                        -- IR 内定位（如 events[12].timeline[7]）
  raw         TEXT,                        -- 原始指令/标签文本
  reason      TEXT,
  kept_assets TEXT,                        -- 保守保留的资源 hash 列表（JSON 数组）
  created_at  TEXT NOT NULL
);
```

## 4. 冷归档字段（DR-9）

`asset_cold` 表字段集与上游 §5.3 完全一致：

| 字段 | 说明 |
|---|---|
| `content_hash` | 内容哈希（与库内资产登记同一主键） |
| `cloud_service` | 云端服务（可多服务并存，**禁止锁死单一网盘**） |
| `cloud_path` | 云端路径或标识 |
| `uploaded_at` | 上传时间 |
| `cloud_checksum` | 云端校验码 |
| `download_method` | 回下载方式 |
| `encrypted` | 是否加密上传（默认 1） |
| `key_hint` | 口令提示（**不存口令本身**） |

## 5. 容量与索引预算（验收用）

| 项目 | 预算 |
|---|---|
| 包内嵌索引（index/） | KB ~ 数 MB/游戏（超限即摄入报错） |
| 中心库 library.db | 预估 100~300 MB（208 万文件量级），WAL 模式 |
| 缩略图 | WebP 最长边 ≤ 512px，LRU 缓存，后台可重建 |
| 资源物理份数 | 每内容 1 份（硬链接去重后） |

---

## 6. 与 IR 的关系

`IR.json` 是包内演出描述，字段级规范见 **03_IR规范.md**，机器可读定义见 **schema/ir.schema.json**。`refs.json` 由 IR 反推生成（FR-03），其 schema 见 **schema/refs.schema.json**。
