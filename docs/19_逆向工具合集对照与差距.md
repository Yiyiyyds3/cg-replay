# 19 · 逆向工具合集对照与差距

> 参考材料：《黄油 / Galgame 逆向工具合集 · 全网盘点》（2026-11-19，553 行，外部只读）。
> 本文回答一个问题：那本合集里的能力，哪些我们已经有了、哪些没有、没有的按什么顺序补。
> 口径提醒：UCGR 是 **CG 重演器**——输入是解包后的游戏目录，输出是可回放的 CG 事件流。
> 汉化组的「提文本 → 翻译 → 回填」流水线、运行期 hook、存档修改三大类**非本项目范围**（理由见 §1 末）。

| 运行期 hook（LunaTranslator / Textractor） | **非本项目范围** | — | — |

**三类「非本项目范围」的理由**：我们是重演器不是汉化工具——①翻译流水线的产出物（改好的游戏文件/补丁包）对我们只是更好的输入，链路本身不归我们；②运行期 hook 抓的是「跑起来的游戏」的内存文本，我们恰恰是给**跑不动/不想跑**的场景提供静态回放，方向相反；③存档修改改的是玩家进度状态，与 CG 事件重建无关。合集里这三类的价值是：当某款游戏只有运行期方案能拿到 CG 时，我们标注「需人工 hook 预提取」。

## 2. 已覆盖实现边界（与合集工具的差异）

- **KiriKiri**：自写 XP3 索引+zlib 解包 + KIF/PNG 解码，不依赖 GARbro。`.ks` 是 UTF-16 明文直接回放；编译剧本走 scn 适配器（PSB）。**边界**：不支援 Cxdec/Hxv4 厂商加密（合集的 KrkrExtract 路线靠注入运行中进程抓密钥，我们是静态解包）；不做 xp3 重打包（不需要——我们不回填）。
- **CatSystem2**：支持 `.cst` 事件粒度（含 update01 覆盖层双树并集）。合集工具（TriggersTools.CatSystem2 / CatSceneEditor）偏重**汉化的解包与场景编辑**，我们偏重**cst 内的演出时序**（图片引用/切换/等待），同一格式不同切面。
- **BGI/Ethornell**：`.bs` 栈式字节码按实测样本的 opcode 表回放；合集的 EthornellTools/BGIKit 偏文本提取回填，且明确要带「作品级 opcode 表切换」——我们的表也按款维护，新作品撞变体就补。
- **Artemis / NeXAS / Nitro+**：剧本粒度回放；Nitro+ 与 NeXAS 与合集不同——我们直接从打包归档（nss.npa / Script.pac）读剧本，不需要先解包。
- **rmmz**：事件来自编辑器序列化的 data/*.json，天然明文；text_lines/voices 目前记 0 是**未探测**不是没有（总报告 §八-1 的诚实声明）。
- **unity**：走导出管线（cg-index.json），与合集的 AssetRipper/AssetStudio（直出工程）是上下游关系：外部工具导资产，我们消费导出物。Mono/IL2CPP 的区分（Assembly-CSharp.dll vs GameAssembly.dll）对导出器内部处理，UI 无感。
- **renpy / media**：PR #8 刚合入，覆盖 7 款 skip 中的 Ren'Py 类目。

## 3. 缺口优先级（黄油出现频率 × 实现难度）

### P0 —— 大作储备，市场出现率最高

| 引擎 | 格式要点（出处） | 现成参考工具 | 我们接入的最小工作 |
|---|---|---|---|
| AliceSoft System4 | ALD 差分归档**必须按序叠加**；AIN 不是脚本是编译后游戏数据（函数表+字符串表+数据表混排，v6–v11 差异大）（§A.3） | [nunuhara/alice-tools](https://github.com/nunuhara/alice-tools)（CLI 全能） | ①external bridge 接 alice-tools 解包 → ②ain 消息表适配器出事件流。库内样本：兰斯10（47 款解包库 .afa） |
| YU-RIS | ypf 简单 XOR+名称哈希好办；**ybn 是栈式 VM 字节码必须反编译**——比 KiriKiri 难的点（§A.4） | [ZQF-ReVN/RxYuris](https://github.com/ZQF-ReVN/RxYuris)（ypf/ybn 解包+ybn 反编译） | ①bridge 接 RxYuris 解包 → ②ybn 反编译产物→事件流适配器 |
| SiglusEngine | scene.pck 是自研 VM 编译字节码，文本躺常量池，不解析拿不到（§A.6） | [xmoezzz/SiglusExtract](https://github.com/xmoezzz/SiglusExtract)、[siglus_rs](https://github.com/xmoezzz/siglus_rs)（Rust 跨平台） | ①bridge 接 SiglusExtract → ②scene 脚本→CG 事件适配器（CG 引用粒度即可，不做全剧本） |

排序说明：P0 三家是商业大作出现率最高的三家（合集口径），但对**现有 117 款库**的直接收益是 0 款（均未命中）；P1 的 Wolf 是库内现款（莱特娜），RMXP/VX/VA 在同人黄油里高频出现、解包算法还不需要密钥，属「低难度高周转」；P2 里 Unreal 虽排后，却是库内 skip 3 款的钥匙——若只看「现有库通过率」，补 Unreal+Wolf 的收益排序高于 P0。

## 4. 借刀：先靠外部 CLI 解包再进现有链

自写适配器之前，大部分缺口引擎可以走**外部解包桥**：`internal/unpack.External`（待实现接口，约定：按引擎调用外部 CLI 解包到指定输出目录，返回解包根），配置字段 `external_unpacker`（引擎名 → CLI 命令模板映射，写在 ucgr-convention.json 或全局配置）。解包产物落盘后，DetectEngine（含本轮新增指纹）认引擎，现有 ScanWith 链原样接管——**我们不写解包代码，只写「调得动工具 + 吃得下产物」**。

**CLI 可用（桥接优先级从高到低）**：
- `arc_unpacker` —— 批量解包，格式覆盖面仅次于 GARbro，且是纯 CLI（[vn-tools/arc_unpacker](https://github.com/vn-tools/arc_unpacker)）
- `alice-tools` —— System4 全家（afa/ald/ain）（§A.3）
- `WolfDec` —— Wolf 解密解包（§B.4）
- `repak` —— Unreal .pak（§B.6）
- `unrpyc` / `rpatool` —— Ren'Py（已适配，兜底用）（§B.1）
- `msg-tool` —— kirikiri/BGI 脚本导出导入（Rust，活跃；我们只用其导出做审计比对）（§3.3）

**GUI only（需人工先导，产物再入库）**：
- GARbro / GARbro-Mod —— 格式最全但要拖拽操作；适合一次性人工解某款
- KrkrExtract / KrkrzExtract —— 加密 xp3 唯一现实解，靠注入运行中进程，永远不可能 CLI 化进桥
- AssetRipper / AssetStudio —— Unity 资产直出工程；我们的 unitycg 导出管线已覆盖大半场景，AssetRipper 留给导出器啃不动的图集/3D 款

## 5. 本机 117 款库的实际分布（为什么这些缺口值得补）

回引 `reports/游戏库验收_总报告.md`（§五/§六/§八，批 4 口径）与 `reports/引擎分布复核报告_2026-10-15.md`（47 款解包库）：

**117 款原始安装库**：pass 53（rmmz 37 + unity 导出重扫 15 + spike 1）/ partial 6（KiriKiri xp3 未解包）/ fail 18 / skip 40。skip 40 款的 engine_guess 分布：**Ren'Py 7（适配器已合入）｜Unreal 3｜Godot 2｜Cocos2d-x 2｜WolfRPG 1｜GameMaker 1｜未知容器 16｜仅 game/ 目录 3｜自研 4｜明醉/Gyu 1**。

**47 款解包库**：KiriKiri 11 / CatSystem2 8 / BGI 4 / NScripter 3 / Unity 3 / Artemis 3 / **AliceSoft(.afa) 1（兰斯10）** / **Eushully 1（封緘のグラセスタ）** / **LiveMaker 1（ORE_TUBA）** / Nitro+ 1，另有单件 11 款。

**结论（按对现有库的边际收益）**：
1. **Unreal**（指纹已认）：117 款库 skip 3 款直接等它——repak 桥是**单位工作量收益最高**的一项。
2. **Wolf RPG**（指纹已认）：skip 1 款（莱特娜）+ 同人黄油高频出现，WolfDec 桥顺手解。
3. **P0 三家（System4/YU-RIS/Siglus）**：现有库 0 命中，是**大作储备**而非存量修复——兰斯10（System4）与封緘のグラセスタ（Eushully）是 47 款解包库里能立刻受益的两款现款。
4. **Godot/Cocos/GameMaker**（合计 5 款 skip）：不在合集覆盖内（合集没有这三个引擎的章节），要补得另起调研——列为对照文档之外的新缺口，别指望这本合集。
