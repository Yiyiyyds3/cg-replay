## 0.5 最小剪枝方案（上游 FINAL 1017 新增 §7.5）

> 目的：**用最小代价验证假设、暴露风险**，不做完整包/中心库/客户端 UI，只跑
> 「一个游戏 × 一个 CG 事件 × 一条路径」。完整流水线（M0→P2）之前的**探针**。

| 层级 | 范围 | 输入 | 输出 | 耗时 |
|---|---|---|---|---|
| S0 体积盘点 | 1 款游戏，按扩展名分类统计体积 | 解包目录 | 各资源类型体积占比表 | ~5 分钟 |
| S1 单事件解析 | 1 个 CG 事件的资源引用列表 | 脚本文件 | 引用列表 + 路径映射结论 | ~30 分钟 |
| S2 单事件裁剪 | 只复制引用到的资源 | 引用列表 + 解包目录 | 资源子集 + 校验报告 | ~1 小时 |
| S3 单事件回放 | 最简方式回放（命令行合成图或最简窗口） | 裁剪资源 + IR | 可播放演出 + 人工比对 | ~半天 |

**剪枝决策表（任一情况 → 对应动作）**：

| 情况 | 动作 |
|---|---|
| S0：CG 图片占比 < 30% | 裁剪空间不如预期，重估目标 |
| S0：动态立绘 > 20% | 最大省空间来源，优先整块删除 |
| S1：路径映射失败率 > 10% | 研究该引擎命名/索引机制 |
| S1：发现加密/混淆 | 暂停，先解决解密 |
| S2：裁剪体积 ≈ 原始体积 | 该事件引用了全游戏资源，调裁剪粒度 |
| S2：发现隐式引用 | 补充保守保留规则 |
| S3：图层顺序错误 | 检查脚本 z-order 语义 |
| S3：人工比对通过 | 该引擎核心逻辑已验证，可扩展 |

**与本项目现状的对应**：Python 原型（ks_refs / cst_refs / ast_refs）已在
**22 款全量**尺度上完成 S1+S2（引用提取 + 匹配 + 保守保留），假设已验证；
Go 实现的剪枝从 **S3（单事件端到端：解析→裁剪→回放→人工比对）**起步，
语言为 Go（上游 1017 §7.5.3 的最小解析器伪代码即 Go）。

**Go 侧最小剪枝进展（2026-10-18）**：S0~S3 已在《重返蓝鲸岛》单事件上**全部跑通** ——
S3 的「可播放演出」已由**库内代码**完成（`internal/replay` + `ucgr replay --render/--gif`，
输入只有 `ir.json` + S2 裁剪产物，掩码 JPEG 由 `internal/decode` 直接解码），
决策表两行 S3 判断为「图层顺序：通过」「人工比对：达成」。
证据、复跑命令与仍存缺口见 `reports/S3_单事件端到端spike_重返蓝鲸岛_2026-10-18.md`
（§7 决策表 / §11 S3 闭环进库 / §12 下一步）。

**S4 · 完整 CG 演出回放（2026-10-18 第四轮，对交付形态的修正）**：S3 的「按时刻采样合成帧/GIF」
被用户判定为**形态错误**（那是「CG 轮播」，丢掉了 BGM/文本/转场/节奏）。交付形态改为
**窗口实时播放器**：把游戏自己那套演出原样重放（双缓冲 fore/back + `[trans]` 过渡 + `[quake]` +
对话框原文的点击节奏），cg-replay 只负责「把各作的完整演出摘出来统一管理」。
- 新概念：**演出台本 `show`**（`internal/ir/show.go` + `internal/adapter/kirikiri/build_show.go`，
  引擎中立的「怎么演」指令流，与扁平 `timeline` 并存于同一份 `ir.json`，校验 **V9**）；
  **播放解释器** `internal/player`（顺序阻塞式 KAG 语义：双缓冲、转场插值、抖动、文本分页与自动推进）；
  **窗口/上屏** `internal/platform/win32`（DIB 画布 + GDI 文字 + user32 消息循环）。
- 入口：`ucgr play <ir.json> --assets <素材根>`（窗口模式，键鼠可推进/暂停/倍速/截图）；
  `--shot <目录> --at ms,…` 出 PNG（离线人工比对用）。
- 验证：`go build/vet/test` 全 0；`71kaigan01.ks` → `show` 14,265 条、IR 校验 V1~V9 通过、
  离线采样 13 帧（0 → 3,550,000 ms）画面正确、窗口模式起窗 10 秒无报错。
- 仍存缺口：字体（GDI 不认 OTF/CFF，退 SimSun，忠实需 GDI+）、音频未接（本作 BGM/SE 素材多为
  84 B 零采样空壳，且 OGG 解码只能走 Media Foundation）、`universal` 转场按 crossfade 回退。
  详见 `reports/S3_单事件端到端spike_重返蓝鲸岛_2026-10-18.md` **§13**。

**S5 · 按原作分割的事件库 + 双击即用的 GUI 回放器（2026-10-18 第五轮）**：
S4 交付后用户第二次修正形态——「应用端应该是 .exe 直接运行的那种」，
且「各个 CG 事件应该按照原本的游戏的分割方式分割，每个 CG 都是单独的事件」。
- **原作自己的分割方式**（实测）：本作把 CG 鉴赏写成 `cgrai.ks`…`cgrai6.ks`（6 页 × 16 格，
  槽位 `cg001`…`cg096`，`[sysbutton graphic="cg017" … call storage="cgrai00.ks"; target=*cg17]`）
  + `cgrai00.ks`（1633 行，每个 `*cgNN` 段 = 一个 CG 事件，含 1~N 页图）；主线则是
  `01kuukou.ks`…`76utyu.ks`（每个编号脚本 = 一个场景事件，79 个）。
- **事件库** `internal/library`：扫出 96 个 CG 事件（含页序列）+ 79 个场景事件，
  可 `Save/Load` 成 JSON 清单；`ucgr events <解包目录> [--out 库.json]` 出清单。
- **标签切片** `internal/adapter/kirikiri/segment.go`：解析时记录脚本标签（`Ast.Labels`），
  按标签段切出「只含演出台本」的事件；`ucgr play --script <脚本.ks> --label cg01` 可直接播某段。
- **GUI 交付物** `cmd/cgreplay`（`bin\cgreplay.exe`，双击即用）：左侧事件列表（96 CG + 79 场景）、
  右侧播放区，双击/回车即播；「选择游戏目录…」换游戏、可重新扫描、上一个/下一个、自动推进、
  F12 截图；配置与库清单落在 exe 同目录（`cgreplay.conf` / `cgreplay-lib.json`）。
  控件层在 `internal/platform/win32/gui.go`；素材解析与合成提为公共函数
  （`replay.GameLoader` / `player.RenderFrame`），CLI 与 GUI 共用。
- **顺带修掉的忠实度问题**：CG 鉴赏每页写作 `[image layer=base … visible=false]`，
  按字面执行会把图隐藏（整屏全黑）；实测原作 base/背景层的可见性无意义（始终绘制），
  故对背景层忽略 `visible=false`（`build_show.go` 的 `isBgLayer`）。
- 验证：`ucgr events` → **96 CG + 79 场景**；cg01 出图由纯黑 → 15,073 色；cg08 8 页可分页推进；
  `71kaigan01.ks` 回归 19,925 色不变；`cgreplay.exe --selftest` 出图与 CLI 同帧；
  起窗冒烟无 stderr、退出正常；`gofmt/build/vet/test` 全 0。提交 `a360934`（10 files +1707/-100）。
- 仍存缺口：与 S4 的四项相同（字体/音频/`universal` 转场/`[img]` 裁剪读法）；多页 CG 第 2 页起
  靠「点击等待」（GUI 手动或 2500 ms 自动推进）；长场景事件（`71kaigan01.ks`）尚未再切段。
  详见 `reports/S3_单事件端到端spike_重返蓝鲸岛_2026-10-18.md` **§14**。

## 12. 任务框架通用要求（DR-10）

## 13. 流水线红线

1. 任何阶段**不得**物理删除非待删区路径上的文件。
2. 摄入失败必须**整游戏回滚**（半成品包不留库）。
3. 降幅数字只出自 M0 报告 + 实测剔除统计，**禁止中间环节拍脑袋**。
4. 核心代码改动需架构变更单——适配器的问题在适配器侧解决。
