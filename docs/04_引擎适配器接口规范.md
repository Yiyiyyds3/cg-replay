## 1. 定位与契约总览

引擎适配器是可插拔模块，实现**五个方法**。契约语言无关（JSON 可序列化边界），参考实现以 Rust trait 给出（核心为 Rust，与 Tauri 壳同语言，移动端换壳成本低）。

```rust
pub trait EngineAdapter {
    /// ① 引擎识别：不确定必须返回 None，禁止瞎猜
    fn identify(&self, archive_or_dir: &Path) -> Option<EngineId>;

    /// ② 归档解析：列出条目（不解压内容）
    fn parse_archive(&self, path: &Path) -> Result<Vec<ArchiveEntry>>;

    /// ③ 脚本解析：产出引擎专有 AST（对核心不透明）
    fn parse_script(&self, bytes: &[u8], ctx: &ScriptCtx) -> Result<ScriptAst>;

    /// ④ 构建 IR：唯一产物契约 = 03 文档全部 MUST 规则
    fn build_ir(&self, ast: &ScriptAst, ctx: &BuildCtx) -> Result<Ir>;

    /// ⑤ 转场注册表：引擎原生转场 id → 实现
    fn transitions(&self) -> TransitionRegistry;
}
```

| 方法 | 输入 | 输出 | 失败语义 |
|---|---|---|---|
| `identify` | 归档文件或解包目录 | `engine_id` 或 `None` | 不抛错；不确定就 None |
| `parse_archive` | 归档路径 | `[ArchiveEntry]` | 归档损坏 → Err，摄入中止并记录 |
| `parse_script` | 脚本原始字节 + 上下文 | 引擎专有 AST | 单脚本失败 → 记录后跳过该脚本，**不中断整个游戏** |
| `build_ir` | AST + 构建上下文 | IR（过 03 文档 V1~V8 校验） | 校验失败 → 摄入失败 |
| `transitions` | — | 注册表 | 恒成功 |

## 2. 数据结构定义

```rust
struct EngineId(pub String);   // "kirikiri" / "artemis" / "catsystem2" / "bgi" /
                               // "nscripter" / "unity_il2cpp" / "fvp" / "baldr" / ...

struct ArchiveEntry {
    path: String,              // 归档内相对路径（统一 '/' 分隔）
    size: u64,
    offset: u64,
    compression: Compression,  // None | Zlib | Lzss | ...
    uncompressed_size: Option<u64>,
    encrypted: bool,
    key_hint: Option<String>,  // 如 XP3 的 adlr 标记、加密算法名
}

struct ScriptCtx<'a> {
    entry_index: &'a EntryIndex,   // 归档条目索引（路径→条目）
    config: &'a AdapterConfig,     // 适配器配置（见 §7）
}

struct BuildCtx<'a> {
    entry_index: &'a EntryIndex,
    config: &'a AdapterConfig,
    log: &'a dyn Logger,                 // 结构化日志
    record_unrecognized: &'a dyn Fn(Unrecognized),  // 未识别登记回调
}

struct TransitionRegistry {
    map: HashMap<String, TransitionImpl>,   // 引擎原生 id → 实现
}

struct TransitionImpl {
    impl_key: String,       // 核心 L0 注册表键，或 tuned 级专有键
    duration_ms: u64,       // 引擎缺省时由适配器给默认值
    params_schema: Value,   // JSON Schema，供回放器校验
}
```

## 3. identify 的判定纪律

1. **签名优先**：魔数 / 目录布局 / 特征文件（如 `xp3` 后缀 + `XP3\r\n` 头、`*.paz` + 特定 ini、`data.xp3` + `*.ks`）。
2. **多适配器竞聘**：核心按注册顺序询问全部适配器；返回多个时取置信度最高者，**平票按注册顺序**并在日志记录歧义。
3. **不确定就 None**：宁可标 `unknown` 让人工介入，也不许错判（错判会导致整游戏裁剪错误，是最高危故障）。
4. **版本探测**：识别到引擎后尽量探测版本（如 KiriKiri1 / KiriKiriZ / 吉里吉里2 系），写入 `package.json.engine_version`。

---

## 4. parse_archive 的通用要求

- 只列条目，不解压全部内容（2M 文件量级下，全量解压不可接受）。
- 必须保留 `offset/size/compression/encrypted`，供后续按需读取与哈希。
- 加密/保护归档（如 XP3 `adlr` 块、BGI 变体）：标 `encrypted=true` + `key_hint`；**密钥/掩码不进 IR、不进包**，仅在摄入会话内使用。
- 输出顺序稳定（按路径排序），保证 `manifest.json` 可复现。

## 5. 转场注册表与回退规则（硬契约）

### 5.1 核心 L0 注册表（generic 级，内置）

| impl_key | 语义 |
|---|---|
| `fade` | 淡入淡出（**默认回退目标**） |
| `slide_left` / `slide_right` | 左右滑入 |
| `zoom` | 缩放过渡 |
| `wipe` | 擦除 |

### 5.2 回退规则

1. 适配器产出的每个转场，`impl` 必须能映射到 L0 注册表键或该引擎 tuned 级专有键；**否则摄入失败**（防止"未实现 id 裸奔"）。
2. 引擎原生 `transition_id` 无法映射时：适配器填 `impl="fade"` + `fallback=true`，**保证不崩、能看**（上游 §4.2 兜底规则）。
3. 回放器遇到 `fallback=true`：正常播放近似效果，调试模式标注「近似转场」。
4. `fidelity=tuned` 的游戏：适配器补齐该引擎转场/特效/排版表（DR-22），专有 impl 由适配器随包分发实现键，核心不改。
5. 回放器遇到未知 impl 键（tuned 包在低版本核心上打开）：**降级为 `fade` 并提示**，绝不容错。

### 5.3 转场元数据要求

每条注册项必须带 `duration_ms` 默认值与 `params_schema`；时长缺失是回放时序错乱的最大来源，适配器**不许省略**。

## 6. 保守保留规则（裁剪安全原则，上游 §9-6）

> 解析器认不出的指令 → **保守保留**其可能引用的资源，并标记"未识别"（宁多勿缺）。

适配器必须实现：

1. **原文照录**：未识别指令写入 `IR.events[].unrecognized[].raw`，附 `node_path` 定位。
2. **路径操作数抽取**：从指令的操作数中抽取"看起来是包内路径"的字符串（含常见资源扩展名，或去掉已知参数名后剩余的可解析串）。
3. **保守入集**：抽取结果能在归档条目索引中命中的，一律加入 `refs.json`（`role=unrecognized`）与 `IR.assets[]`。
4. **双向登记**：`unrecognized[].kept_assets` 与实际入集保持一致（IR 校验 V6）。
5. **TJS 二进制脚本 / 加密脚本**：整文件标记未识别，脚本原文仍按 DR-25 原样入库；其引用的资源在**无证据表明无关**时保守保留。

## 7. AdapterConfig（适配器配置）

每个适配器一份 `adapter.toml`，随适配器版本化分发：

```toml
engine_id = "kirikiri"
adapter_version = "0.1.0"
core_api_version = "1"          # 契约版本；不匹配时核心拒绝加载
formats = ["xp3", "ks-dir"]
fidelity_default = "generic"
dependencies = []

[config]
# CG 事件判定规则（路径白名单 + 指令类型双通道；不确定时并入相邻 scene 事件）
cg_path_patterns = ["evimage/", "cg/", "image/ev/", "still/"]
event_video_patterns = ["video/", "mu/", "movie/"]
script_extensions = ["ks", "ksc", "sks", "txt"]
```

**规则**：配置只影响"事件怎么切、哪些路径算 CG"，**不影响 IR 语义**；改配置不需要改核心。

## 8. 测试契约（每个适配器必交）

1. **fixture 测试**：最小样本归档（或脱敏摘录）+ 期望 IR（golden），`cargo test -p adapter-<engine>` 必须全绿。
2. **round-trip 测试**：`build_IR(parse_script(bytes))` 对 fixture 输出稳定（哈希级稳定）。
3. **未知指令注入测试**：fixture 里塞未识别指令，断言其进入 `unrecognized` 且资源被保守保留。
4. **真机样本测试**（P2 起强制）：至少 1 个真实游戏的解析报告（事件数、资产数、unrecognized 数）存档，作为回归基线。

## 9. KiriKiri 适配器规格（P0 首发）

> ⚠️ XP3 的**精确字节布局**（魔数尾字节、索引块签名、压缩标志位）以 M0/P0 阶段对真实样本的实测为准；本文档只约定到"可分块解析"的层级，实现时按实测校准并在本文档留痕。

### 9.1 identify

- 归档：`*.xp3`，头部 `XP3\r\n \n\x1a` 前缀 → `kirikiri`；进一步探测 KiriKiriZ 特征 → 版本标注。
- 目录：存在 `*.xp3` + `*.ks`/`*.ksc` 脚本 + `data.xp3` 式命名 → `kirikiri`。
- 其余情况返回 `None`。

### 9.2 parse_archive

- 按「4 字节 ASCII 块签名 + 8 字节 LE 块长 + 载荷」的分块结构解析；文件条目含：路径、原始大小、压缩大小、压缩标志、加密标志。
- `adlr` 类块（名称哈希块）出现即标 `encrypted=true`，`key_hint` 记录块类型。
- 输出 `ArchiveEntry[]`（路径排序）。

### 9.3 parse_script

- 文本标签脚本（`.ks/.ksc/.sks/.txt`）：按行切分，`[tag ...]` 为指令，其余为文本行；标签属性按 `key=value` 解析（值可能带引号）。
- TJS 二进制脚本：**标记未识别**，原文入库（§6-5）。
- 指令最小集（P0 必须认）：`bg` / `cg` / `chara_new` / `chara_c` / `chara_del` / `playbgm` / `stopbgm` / `playse` / `vo` / `movie` / `trans` / `wait` / `ws` / `l` / `p` / `cm` / `jump` / `click` / `if` / `eval` / `sel` / `quake`。

### 9.4 build_IR（事件切分）

- **事件边界**：CG 展示指令（`cg`，或 `bg` 引用命中 `cg_path_patterns`）开启一个 `still_cg` 事件；`movie` 指令产出 `event_video` 事件；两者之间的演出（立绘进出、对白、语音、BGM、转场）归入该事件。
- **无法判定归属的演出**：并入相邻 scene 事件（保守，宁多勿缺）。
- **图层映射**：`bg`→background；`chara_*`→stand（差分由不同 storage 路径体现）；`cg`→cg。
- **转场映射**：`trans method=X time=T` → `transition_id=X`，按注册表映射 impl；X 未注册 → `fade` + `fallback=true`。
- **文本/语音**：标签间文本行→`texts`；`vo` 指令按与文本的位置对应关系绑定 `voice`（对不上时置 null 并登记 unrecognized）。
- **分支**：`sel`/`jump`/`if` 产出 `branches`（默认走引擎给出的首个分支）。

### 9.5 transitions（P0 初版）

| KiriKiri `method` | impl | 说明 |
|---|---|---|
| `crossfade` | `fade` | L0 |
| `fade` / `fadeout` / `fadein` | `fade` | L0 |
| `slide` 系 | `slide_left` / `slide_right` | 按 direction 参数 |
| `zoom` 系 | `zoom` | L0 |
| 其余（`blind`、`check`、`swirl`…） | `fade` + `fallback=true` | P1/P2 按需升 tuned |

## 10. 新引擎落地流程（DR-20 预留余量的操作化）

1. 确认引擎样本可读（M0 已清点体积）。
2. 建 `adapter-<engine>` crate，实现五方法（先 `identify` + `parse_archive`）。
3. 补 fixture + golden IR（§8-1），跑通 `build_IR` 与 IR 校验。
4. 接入摄入流水线（05 文档阶段 B），跑 1 个真实游戏出解析报告。
5. 人工抽查 ≥ 3 个事件的演出比对（误裁检测第三层）。
6. 更新本文档 §9 同级的引擎规格小节 + 07 文档引擎队列状态。
7. **核心代码零改动**是验收项：若需改核心，先走架构变更单。
