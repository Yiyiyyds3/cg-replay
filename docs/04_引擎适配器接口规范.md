## 1. 定位与契约总览

引擎适配器是可插拔模块，实现**五个方法**。契约语言无关（JSON 可序列化边界），参考实现以 **Go interface** 给出（2026-10-17 技术栈由 Tauri+Rust 切换为 **Wails+Go**：Go 编译秒级、goroutine 适配 208 万文件并发扫描、SQLite/BLAKE3 绑定成熟；切换理由详见上游 FINAL 1017 §10.1）。

```go
// EngineAdapter 引擎适配器契约（五方法）
type EngineAdapter interface {
    // ① 引擎识别：不确定必须返回 ""，禁止瞎猜
    Identify(archiveOrDir string) (string, error)

    // ② 归档解析：列出条目（不解压内容）
    ParseArchive(path string) ([]ArchiveEntry, error)

    // ③ 脚本解析：产出引擎专有 AST（对核心不透明）
    ParseScript(data []byte, ctx *ScriptCtx) (ScriptAst, error)

    // ④ 构建 IR：唯一产物契约 = 03 文档全部 MUST 规则
    BuildIR(ast ScriptAst, ctx *BuildCtx) (*IR, error)

    // ⑤ 转场注册表：引擎原生转场 id → 实现
    Transitions() TransitionRegistry
}
```

| 方法 | 输入 | 输出 | 失败语义 |
|---|---|---|---|
| `identify` | 归档文件或解包目录 | `engine_id` 或 `None` | 不抛错；不确定就 None |
| `parse_archive` | 归档路径 | `[ArchiveEntry]` | 归档损坏 → Err，摄入中止并记录 |
| `parse_script` | 脚本原始字节 + 上下文 | 引擎专有 AST | 单脚本失败 → 记录后跳过该脚本，**不中断整个游戏** |
| `build_ir` | AST + 构建上下文 | IR（过 03 文档 V1~V8 校验） | 校验失败 → 摄入失败 |
| `transitions` | — | 注册表 | 恒成功 |

## 2. 数据结构定义

```rust
struct EngineId(pub String);   // "kirikiri" / "artemis" / "catsystem2" / "bgi" /
                               // "nscripter" / "unity_il2cpp" / "fvp" / "baldr" / ...

struct ArchiveEntry {
    path: String,              // 归档内相对路径（统一 '/' 分隔）
    size: u64,
    offset: u64,
    compression: Compression,  // None | Zlib | Lzss | ...
    uncompressed_size: Option<u64>,
    encrypted: bool,
    key_hint: Option<String>,  // 如 XP3 的 adlr 标记、加密算法名
}

struct ScriptCtx<'a> {
    entry_index: &'a EntryIndex,   // 归档条目索引（路径→条目）
    config: &'a AdapterConfig,     // 适配器配置（见 §7）
}

struct BuildCtx<'a> {
    entry_index: &'a EntryIndex,
    config: &'a AdapterConfig,
    log: &'a dyn Logger,                 // 结构化日志
    record_unrecognized: &'a dyn Fn(Unrecognized),  // 未识别登记回调
}

struct TransitionRegistry {
    map: HashMap<String, TransitionImpl>,   // 引擎原生 id → 实现
}

struct TransitionImpl {
    impl_key: String,       // 核心 L0 注册表键，或 tuned 级专有键
    duration_ms: u64,       // 引擎缺省时由适配器给默认值
    params_schema: Value,   // JSON Schema，供回放器校验
}
```

## 3. identify 的判定纪律

1. **签名优先**：魔数 / 目录布局 / 特征文件（如 `xp3` 后缀 + `XP3\r\n` 头、`*.paz` + 特定 ini、`data.xp3` + `*.ks`）。
2. **多适配器竞聘**：核心按注册顺序询问全部适配器；返回多个时取置信度最高者，**平票按注册顺序**并在日志记录歧义。
3. **不确定就 None**：宁可标 `unknown` 让人工介入，也不许错判（错判会导致整游戏裁剪错误，是最高危故障）。
4. **版本探测**：识别到引擎后尽量探测版本（如 KiriKiri1 / KiriKiriZ / 吉里吉里2 系），写入 `package.json.engine_version`。

---

## 4. parse_archive 的通用要求

- 只列条目，不解压全部内容（2M 文件量级下，全量解压不可接受）。
- 必须保留 `offset/size/compression/encrypted`，供后续按需读取与哈希。
- 加密/保护归档（如 XP3 `adlr` 块、BGI 变体）：标 `encrypted=true` + `key_hint`；**密钥/掩码不进 IR、不进包**，仅在摄入会话内使用。
- 输出顺序稳定（按路径排序），保证 `manifest.json` 可复现。

## 5. 转场注册表与回退规则（硬契约）

### 5.1 核心 L0 注册表（generic 级，内置）

| impl_key | 语义 |
|---|---|
| `fade` | 淡入淡出（**默认回退目标**） |
| `slide_left` / `slide_right` | 左右滑入 |
| `zoom` | 缩放过渡 |
| `wipe` | 擦除 |

### 5.2 回退规则

1. 适配器产出的每个转场，`impl` 必须能映射到 L0 注册表键或该引擎 tuned 级专有键；**否则摄入失败**（防止"未实现 id 裸奔"）。
2. 引擎原生 `transition_id` 无法映射时：适配器填 `impl="fade"` + `fallback=true`，**保证不崩、能看**（上游 §4.2 兜底规则）。
3. 回放器遇到 `fallback=true`：正常播放近似效果，调试模式标注「近似转场」。
4. `fidelity=tuned` 的游戏：适配器补齐该引擎转场/特效/排版表（DR-22），专有 impl 由适配器随包分发实现键，核心不改。
5. 回放器遇到未知 impl 键（tuned 包在低版本核心上打开）：**降级为 `fade` 并提示**，绝不容错。

### 5.3 转场元数据要求

每条注册项必须带 `duration_ms` 默认值与 `params_schema`；时长缺失是回放时序错乱的最大来源，适配器**不许省略**。

## 6. 保守保留规则（裁剪安全原则，上游 §9-6）

> 解析器认不出的指令 → **保守保留**其可能引用的资源，并标记"未识别"（宁多勿缺）。

适配器必须实现：

1. **原文照录**：未识别指令写入 `IR.events[].unrecognized[].raw`，附 `node_path` 定位。
2. **路径操作数抽取**：从指令的操作数中抽取"看起来是包内路径"的字符串（含常见资源扩展名，或去掉已知参数名后剩余的可解析串）。
3. **保守入集**：抽取结果能在归档条目索引中命中的，一律加入 `refs.json`（`role=unrecognized`）与 `IR.assets[]`。
4. **双向登记**：`unrecognized[].kept_assets` 与实际入集保持一致（IR 校验 V6）。
5. **TJS 二进制脚本 / 加密脚本**：整文件标记未识别，脚本原文仍按 DR-25 原样入库；其引用的资源在**无证据表明无关**时保守保留。

## 7. AdapterConfig（适配器配置）

每个适配器一份 `adapter.toml`，随适配器版本化分发：

```toml
engine_id = "kirikiri"
adapter_version = "0.1.0"
core_api_version = "1"          # 契约版本；不匹配时核心拒绝加载
formats = ["xp3", "ks-dir"]
fidelity_default = "generic"
dependencies = []

[config]
# CG 事件判定规则（路径白名单 + 指令类型双通道；不确定时并入相邻 scene 事件）
cg_path_patterns = ["evimage/", "cg/", "image/ev/", "still/"]
event_video_patterns = ["video/", "mu/", "movie/"]
script_extensions = ["ks", "ksc", "sks", "txt"]
```

**规则**：配置只影响"事件怎么切、哪些路径算 CG"，**不影响 IR 语义**；改配置不需要改核心。

## 8. 测试契约（每个适配器必交）

1. **fixture 测试**：最小样本归档（或脱敏摘录）+ 期望 IR（golden），`go test ./internal/adapters/<engine>/...` 必须全绿。
2. **round-trip 测试**：`build_IR(parse_script(bytes))` 对 fixture 输出稳定（哈希级稳定）。
3. **未知指令注入测试**：fixture 里塞未识别指令，断言其进入 `unrecognized` 且资源被保守保留。
4. **真机样本测试**（P2 起强制）：至少 1 个真实游戏的解析报告（事件数、资产数、unrecognized 数）存档，作为回归基线。

## 9. KiriKiri 适配器规格（P0 首发）

> ⚠️ XP3 的**精确字节布局**（魔数尾字节、索引块签名、压缩标志位）以 M0/P0 阶段对真实样本的实测为准；本文档只约定到"可分块解析"的层级，实现时按实测校准并在本文档留痕。

### 9.1 identify

- 归档：`*.xp3`，头部 `XP3\r\n \n\x1a` 前缀 → `kirikiri`；进一步探测 KiriKiriZ 特征 → 版本标注。
- 目录：存在 `*.xp3` + `*.ks`/`*.ksc` 脚本 + `data.xp3` 式命名 → `kirikiri`。
- 其余情况返回 `None`。

### 9.2 parse_archive

- 按「4 字节 ASCII 块签名 + 8 字节 LE 块长 + 载荷」的分块结构解析；文件条目含：路径、原始大小、压缩大小、压缩标志、加密标志。
- `adlr` 类块（名称哈希块）出现即标 `encrypted=true`，`key_hint` 记录块类型。
- 输出 `ArchiveEntry[]`（路径排序）。

### 9.3 parse_script

- 文本标签脚本（`.ks/.ksc/.sks/.txt`）：按行切分，`[tag ...]` 为指令，其余为文本行；标签属性按 `key=value` 解析（值可能带引号）。
- TJS 二进制脚本：**标记未识别**，原文入库（§6-5）。
- 指令最小集（P0 必须认）：`bg` / `cg` / `chara_new` / `chara_c` / `chara_del` / `playbgm` / `stopbgm` / `playse` / `vo` / `movie` / `trans` / `wait` / `ws` / `l` / `p` / `cm` / `jump` / `click` / `if` / `eval` / `sel` / `quake`。

### 9.4 build_IR（事件切分）

- **事件边界**：CG 展示指令（`cg`，或 `bg` 引用命中 `cg_path_patterns`）开启一个 `still_cg` 事件；`movie` 指令产出 `event_video` 事件；两者之间的演出（立绘进出、对白、语音、BGM、转场）归入该事件。
- **无法判定归属的演出**：并入相邻 scene 事件（保守，宁多勿缺）。
- **图层映射**：`bg`→background；`chara_*`→stand（差分由不同 storage 路径体现）；`cg`→cg。
- **转场映射**：`trans method=X time=T` → `transition_id=X`，按注册表映射 impl；X 未注册 → `fade` + `fallback=true`。
- **文本/语音**：标签间文本行→`texts`；`vo` 指令按与文本的位置对应关系绑定 `voice`（对不上时置 null 并登记 unrecognized）。
- **分支**：`sel`/`jump`/`if` 产出 `branches`（默认走引擎给出的首个分支）。

### 9.5 transitions（P0 初版）

| KiriKiri `method` | impl | 说明 |
|---|---|---|
| `crossfade` | `fade` | L0 |
| `fade` / `fadeout` / `fadein` | `fade` | L0 |
| `slide` 系 | `slide_left` / `slide_right` | 按 direction 参数 |
| `zoom` 系 | `zoom` | L0 |
| 其余（`blind`、`check`、`swirl`…） | `fade` + `fallback=true` | P1/P2 按需升 tuned |

## 10. 新引擎落地流程（DR-20 预留余量的操作化）

1. 确认引擎样本可读（M0 已清点体积）。
2. 建 `internal/adapters/<engine>/` Go 包，实现五方法（先 `Identify` + `ParseArchive`）。
3. 补 fixture + golden IR（§8-1），跑通 `build_IR` 与 IR 校验。
4. 接入摄入流水线（05 文档阶段 B），跑 1 个真实游戏出解析报告。
5. 人工抽查 ≥ 3 个事件的演出比对（误裁检测第三层）。
6. 更新本文档 §9 同级的引擎规格小节 + 07 文档引擎队列状态。
7. **核心代码零改动**是验收项：若需改核心，先走架构变更单。

### 11.1 NScripter 适配器规格（v1）

- **剧本**：整作一份 `nscript.dat`（每字节 XOR 0x84 的 CP932 明文，密文/明文按
  关键字嗅探自动区分）或 `0.txt` / `00.txt`。密钥嗅探取 `;value` / `*define` /
  `numalias` / `stralias`——寒蝉解的剧本解出来以空行开头，首字节判断会误判。
- **词法**：`;` 注释（07th 用 `;＜名前` 给上一行台词标说话人）、`*` 标签、
  半角/全角空格与「『开头为台词行；其余行首字段是纯小写 ASCII 才算命令
  （`!s0「…`、`@…` 这类内联标记前缀的台词行靠它兜底）；`:` 连写多条命令
  （引号内不拆）；define 块里没有台词（缩进的 dim 也是命令）。
- **图像参数**：`bg sora` 这类裸名是**不带 `$` 的 stralias**（07th 惯例），
  解析顺序 = `$别名` → 已是路径 → stralias 大小写不敏感查表 → 原样。
- **归档**：NSA/SAR 大端索引（u16 数量 + u32 base；条目 = 名字\0 + u8 压缩类型
  + u32 相对偏移 + u32 长度 + u32 原始长）；压缩 0=无 / 1=SPB / 2=LZSS(EI=8,
  EJ=4) / 3=NBZ(bzip2)。SPB 解出 24bpp BMP（蛇形行序），bzip2 用标准库。
- **事件切分**：与 BGI 同口径——已有台词又换背景即开新事件；说话人取
  `;＜` 注释；voice 命令绑最近台词；select/selgosub 产出 Branch；
  其余命令按命令名聚合 Unrecognized。
- **回放**：画布 640×480（散装图推断不出时兜底）；小舞台字号 26px；
  台词层 "text"，对话框几何由 MessageBoxOps 前置。
- **实测**：寒蝉解 5636 事件 / 51975 台词、海猫出题 8270 事件 / 46083 台词
  （图全在 arc.nsa，SPB 解图验证通过）、海猫散 10326 事件；三款均完成
  离线出图抽样（背景 + 立绘 + 台词三层合成正确）。

### 11.2 NeXAS 适配器规格（v1，GIGA BALDR 系）

- **PAC 容器**（Baldr Sky Steam 实测破解）：头 12 字节 = `PAC` + 标记字节
  （值任意，GARbro 拒绝 `PACK` 属过度保守）+ i32 条目数 + i32 打包版本
  （4=zlib / 3=LZSS / 0=直存 / 7=zstd）。数据区自 12 起连续压缩流；索引在
  尾部（末 4 字节 = 索引字节数），逐字节取反后 NeXAS-Huffman 解码；
  条目 76 字节 = name[64] + offset + decodedLen + encodedLen。Baldr Sky
  Steam 打包器尾部不补位 → 索引差 3 字节，残缺条目按
  `offset=prevEnd、encoded=索引区起点上界` 兜底（zlib 自描述可解）。
- **NeXAS-Huffman**：MSB-first 位流；1=内部节点（token 递增，先左后右），
  0=叶子 + 8 位符号；树最多 256 槽。**NeXAS LZSS**：窗口 4096、最长匹配
  18、阈值 2、标志字节 MSB-first。
- **.bin 脚本双头变体**：Steam（2019）= u64[0]=n → 文本区 (n+1)*8；
  DIVEX（2012）= u32[1]=n → 文本区 n*8（头为 u32 指令块）。文本区为
  GBK/CP932 C 字符串段落 + null 分隔；DIVEX 段间夹二进制指令字节 →
  宽松扫描器（跳过控制字节，连续 64 个非法才停）。
- **段落语义**：`@v<语音号>「…」` 台词（@n 换行 / @k 停顿 / `@r正文@读音@`
  注音三态状态机）、短段说话人、`#` 标签、`*.png` 等资源、`*.bin` 分支引用、
  大写/数字开头纯 ASCII = 指令（优先于长正文判定，防 `RE_Hit02` 被吞）。
- **编码判别**（实测完全可分）：文本逐段 `decodeSegAuto`——CP932 解出平假名
  率 >0.12 → 日文段，否则 GBK（日文脚本 0.405 vs 中文 0.000）；条目名
  `namesVoteCP` 用**纯 Go** `cp932WellFormed` 投票（Windows
  MB_ERR_INVALID_CHARS 太宽容，区分度不足；GBK 汉字第二字节大量落在 CP932
  非法区 FD-FE → Steam 版非法率 >25% 判 GBK）。
- **图像**：全在 Bmp.pac / Stand.pac / System.pac，标准 PNG/BMP 头直读，
  无需 ies 转换；舞台 1024×768（立绘高 ~775 贴底）。正文场景无背景图引用
  （黑底，背景由引擎 .spm/状态机接管）——v1 接受。
- **事件切分**：一个 .bin = 一个场景事件；SegText → TextLine+Show 三连；
  SegSpeaker 绑说话人；@v → `<语音号>.ogg` 语音资产；连续 SegBranch →
  Branch 选项去重；clockPerCmd=40 / clockPerMsg=600。
- **实测**：Baldr Sky Steam 203 场景事件（章节标题背景图 + 中文正文 +
  对话框几何 0,558,1024,210 出图验证）；DIVEX 141 场景事件（CP932 名字
  「01門倉運輸の日常01」等显示正确）。

### 11.3 Nitro+ 适配器规格（v1，SDActi / NPA 系，鬼哭街重制版实测破解）

- **NPA 容器**：头 41 字节 = `NPA\x01` + 3 填充 + i32 key1 + i32 key2 +
  u8 compressed(15) + u8 encrypted(16) + i32 total + i32 folder + i32 files
  + 8 保留 + u32 dirSize(37)。目录区自 41 起，条目步长 4+nameLen+17
  （i32 nameLen + 加密名 + u8 类型 1=目录/2=文件 + i32 folderId + u32 off
  + u32 size + u32 unpacked）；数据真实偏移 = dirSize + off + 41。
- **名字解密**：`raw[x] += 0xFC*x - arcKey 各字节右移 - index 各字节右移`
  （sar 语义，**index 是含目录条目的循环序号**，不是文件序号——搞错会整包
  名字错位）；arcKey = key1*key2（int32 环绕）。
- **内容解密**：256 字节置换表按 scheme 派生（表由 GARbro GenerateKeyTable
  权威实现生成，仅前 0x1000+len(rawName) 字节加密，解密 =
  `keyTable[buf[i]] - key - i`）。鬼哭街重制版 scheme = Kikokugai
  （NameKey 0x20101118，同组 Axanael/Sonicomi/LostX）。
- **内容 key 派生（关键实测发现）**：Garbro 的公式用加密名（RawName），
  重制版实际用**解密后的明文名**：
  `key = ((nameKey - Σ(明文名 CP932 字节)) * len + arcKey) * unpacked & 0xff`
  ——两类 key 都试（明文名优先），魔数校验兜底。全 4 包 3354 条目 100% 通过。
- **压缩**：compressed=1 时 zlib 流（尾部未加密段无害，
  `zlib.NewReader` 流式解到流尾即可）。
- **NSS 明文脚本**：类 C 语法（scene 块 + if/goto + 引擎命令）；编码判别
  按「CP932 解出平假名占 CJK 比例 >0.1 → 932，否则 GBK」——汉化版游戏
  优先读 nss-1.npa（GBK 覆盖包），同一适配器自动分流。
- **段落语义**：`<PRE @boxN>…</PRE>` 文本块（`//【说话人】`、
  `<voice src="voice/…">` 绑本块台词、`<RUBY>` 注音取内文、`<k>` 换页）；
  `CreateTextureEX(…,"cg/bg/…jpg")` / `OnBG(10,"B_…")`（→ cg/bg/名.jpg，
  大小写不敏感）；`SoundPlay("@m07")` → bgm/m07.ogg。
- **事件切分**：一个 .nss = 一个场景事件（EventID `<脚本名>#001`）；
  首个 /bg/ 引用落背景层，其余登记资产；SegText → TextLine +
  text_clear/text/text_wait 三连；clockPerCmd=40 / clockPerMsg=600；
  舞台 1024×768，对话框几何 MessageBoxOps 前置。
- **实测**：鬼哭街重制版（1.67 GB）——nss.npa 81 脚本全解、cg.npa 2842 张
  （ev 789/st 739/sys 522/fw 246/bg 228）、sound.npa 350 OGG；事件库
  61 场景事件（汉化覆盖包 nss-1.npa 同格兼容，按编码自动分流）；CLI 出图
  抽样验证（背景 + 日文正文 + 对话框三层合成正确，CP932 无乱码）。

### 11.4 AliceSoft System 4 适配器规格（v1，AIN / AFA 系，兰斯10 实测破解）

- **AIN 容器**：头 16 字节 = `AI2\0` + u32(0) + u32 packed + u32 raw，其后整文件
  zlib；解压产物是区段流（tag 4 字节 ASCII + 内容，长度由 tag 语义决定）。
  兰斯10 v12 区段集：VERS / CODE（u32 size + data）/ FUNC（37698 个）/
  GLOB / STRT / MSG1（269676 条加密消息）/ MAIN / HLL0（36 库）/ SWI0 /
  GVER / STR0（15953）。v12 **无** MSG0/FNAM/OJMP（major_version<12 才有）；
  区段流按顺序状态机解析（盲扫描会撞上内容里恰好的 "FUNC" 字节）。
- **FUNC 条目（v12）**：address(i32) + name(zstr, GBK) + type(data/struc/rank)
  + nr_args + nr_vars + is_lambda + crc + vars[name+name2+type+initval]；
  initval 按 vtype 分流（STRING=12→zstr、STRUCT=13/DELEGATE=63/ARRAY=79→跳过、
  其余→i32；rank 非 0 时循环读子类型）。
- **MSG1 解密**：每条 = u32 len + len 字节，`b[i] -= i; b[i] -= 0x60`。
- **opcode 表（v12）**：指令 = u16 opcode + nargs×i32；CALLHLL(0x5a) 在
  v11+ 是 3 参（lib, func, ?）；SH_* 0xb2 起连续 63 条、DG_* 0xf1 起 17 条。
- **事件切分**：函数名含 CJK = 原作场景函数（「萨娜琪亚／参战」，
  系统函数是 ASCII 名）→ `SceneFuncs()`；函数内线性反汇编收集
  S_PUSH(0x41, STR0 索引，立绘/CG 名) 与 MSG(0x59, 消息索引，台词) 序列。
  一个场景函数 = 一个场景事件（EventID = 函数名）。
- **AFA 归档（AlicArch v2）**：头 44 字节 = `AFAH` + u32(0x1c) + "AlicArch" +
  u32 version + u32 unk + u32 dataStart + `INFO` + u32 tablePacked +
  u32 tableUnpacked + u32 nrFiles；表 zlib @44；条目 = u32 nameLen +
  u32 strLen + name[strLen]（GBK 含尾 \0）+ 16 字节尾（off/size 在末 8 字节）；
  条目数据 @ dataStart + off。兰斯10：CG.afa 3460（425 ajp+952 qnt+2083 dcf）、
  CG2.afa 4243（4203 ajp）、Flat.afa 1907、Sound.afa 462 OGG。
- **图像解码（decode 包）**：
  - **AJP**：头 16 字节 XOR 密钥 `5d91ae874a5641cd83ec4c92b5cb1634`
    （仅 JPEG 块与 mask 块**开头各 16 字节**），w/h/jpeg_off/jpeg_size/
    mask_off/mask_size @12；mask 三态 zlib(0x78)/webp/pms8——兰斯10 实测
    全 zlib 或无 mask，mask 字节即 alpha。
  - **QNT**：双布局（rsv0==0 → hdr 固定 48、字段 @8 起；rsv0!=0 →
    hdr_size @8、字段 @12 起，兰斯10 rsv0=2）。像素 zlib 解压到
    ((w+1)&~1)×((h+1)&~1)×3，按「平面(R,G,B)→2×2 块行→块列」重排 +
    减法预测还原（首行 pic[x]=pic[x-1]-pic[x]、首列 pic=上-当前、
    其余 pic=((上+左)>>1)-当前，8 位截断；C 的 uint8 提升语义在 Go 里
    要显式 int 运算）。alpha 不做 2×2 重排，行优先 + 奇宽补位。
  - **DCF 差分**：`dcf ` 头（version 1 / bpp 32）+ base 名（字节循环左移
    rot=(len%7)+1 解密，**假后缀 .png 实际是 QNT 内容**）+ dfdl 段
    （zlib chunk map，首 u32=size-4 校验，0=16×16 差异块）+ dcgd 段
    （完整尺寸差分 QNT）。合成 = 底图上按 chunk map 贴 16×16 差异块 +
    边缘余量整条。**底图链式**（差分４→差分２→原图）需递归；
    底图悬空（兰斯10 存在未被引用的差分）按 libsys4 同款降级直解差分。
- **名字域**：AFA 条目名与事件资产名都是 UTF-8（解码时 GBK→UTF-8），
  回放池同域查找；DCF 底图名是 GBK 原始字节，需 decodeGBK 转换；
  裸名匹配的分隔符两域不同（UTF-8 "/" vs GBK a3 af vs UTF-8 全角／），
  归一化统一走 normKey（小写 + ／→/）。
- **接线**：library/ScanAlice（Rance10.ain → 场景函数清单）→
  replay/afapool（第五兜底池，*.afa 全量合并 + DCF 池内递归）→
  play `--script Rance10.ain --label <函数名>`。
- **实测**：兰斯10（3.80 GB）——AIN v12 全解析（37698 函数 / 269676 消息 /
  15953 字符串）、AFA 表 3460 条 off/size 全验证、事件库 7256 场景事件；
  CLI 出图验证（萨娜琪亚参战场景：DCF 立绘递归合成 + GBK 台词 + 对话框
  三层合成正确；decode 包 QNT round-trip 双布局 + AJP 合成 + 真实语料
  三格式抽测全绿）。

### 11.5 Wolf RPG Editor 适配器规格（v1，Wolf 引擎，塔纳托斯实测破解）

- **引擎识别**：游戏根目录含 `Game.exe` + `data/BasicData/CommonEvent.dat`，
  data/ 子目录为 Wolf RPG Editor 标准布局（BasicData/BattleEffect/CG/
  CharaChip/CharaGraphic/MapData/Picture/SE/Voice…）。M0 报告原判「KSHARK
  自制明文引擎」，实测为 Wolf RPG（`.mps` 头 `WOLFM`、Game.exe 三件套）。
- **容器**：`.dat`/`.mps` 未加密（头部 At(1)==0x50 才是加密容器，本作不是）。
  文件 = u8 indicator(0x00) + 9 字节 magic + u8 version + 数据体。
  magic 第 5 字节（utf8Idx）为 0x55 表示字符串 UTF-8（带尾 \0），0x4C 为
  Shift-JIS——**与兰斯10 的 AFA UTF-8 标记同款套路**。version 0x93/0xCC
  （CommonEvent）或 ≥0x65（Map）走 LZ4 容器，本作 0x90 / 0x64 均直读。
- **指令流（自描述 TLV）**：`u8 intArgCount+1 → i32 opcode → i32×N → u8
  indent → u8 strCount → string×N（u32 len + bytes + \0）→ u8 terminator`；
  terminator 0x01 = Move 扩展（5B + 1B + i32 路线点数 + N×(u8 id + u8 argc
  + i32×argc + "01 00")）。
- **关键 opcode**（WolfTL 命令表）：101=Message、102=Choices、140=Sound、
  150=Picture、210/300=CommonEvent(ByName)、111/112=条件、499=分支结束。
  Picture 的 `args[0]>>4 & 7` 是来源类型（0=file），文件名在 stringArgs[0]，
  槽位号 args[1]。
- **CommonEvent.dat**：u32 事件数 + 每事件（0x8E 头 + intId + 名字 + 命令
  数组 + 描述 + 0x8F + 4 组计数数组 + 0x1D 字节 + 定长 100 字符串 + 0x91
  + 可选 0x92 尾段）。塔纳托斯 511 个 CE / 89840 指令。
- **.mps 地图**：20 字节 magic + version + tileset/width/height + 事件数
  + tiles + N×(0x6F + 事件) + 0x66；事件 = "39 30 00 00" + id + 名字 + x/y
  + page 数 + 0x00000000 + N×(0x79 + Page) + 0x70；Page 含 graphicName
  （事件立绘图）与命令数组，0x7A 结尾。
- **事件切分**：剧情主体在 CommonEvent 按章节组织（「善第1-5章」「悪第
  2-4章」「世間話」等）；地图事件多为触发器（3003 page 仅 177 条 Message
  且大头是 Debug 图测试文本）。v1 以「含 Message 的 CommonEvent」为场景
  事件单元（ID=CE编号、Title=CE 名字），地图事件不入库——地图事件的
  Message 台词约占全作 2.4%，作为已知取舍记录。
- **文本宏清理**：`\cdb[x:y:z]`（数据库说话人引用）、`\cself[N]`（变量）、
  `\i[N]`（图标）、行首 `@N`（文本速度）在回放端无法求值，保守删除；
  `\n` 与未知宏保留。
- **舞台**：800×600（data/Picture/screen.png 背景实际尺寸；DetectStageSize
  会被 3200×4800 的高清 CG 带偏，故 wolf 固定不推断）。高清 CG 原作运行
  时缩放显示，player 的图层合成不缩放——v1 接受溢出裁切，Picture 参数的
  显示尺寸逆向留 v2。小舞台字号 24px。
- **接线**：library/ScanWolf → play `--script CommonEvent.dat --label <CE
  编号>`；GameLoader 的 assetDirs 增加 data/data/CG 等候选（Picture 引用
  相对 data/）。
- **实测**：塔纳托斯（5.26 GB）——CommonEvent.dat 全量解析（511 CE /
  89840 指令 / 5837 Message）、120 个 .mps 全量解析（3003 page）、事件库
  176 个剧情 CE（跳过 335 个系统 CE）；CLI 出图验证（善第1章：夜空背景 +
  月光图层 + 中文台词 + 对话框，宏清理生效，24px 字号无溢出）。
