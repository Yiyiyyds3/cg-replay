## ③ 推进顺序（评价分组，低 → 高）

```
大雷 → 很牢 → 牢 → 拉 → 一搬 → 一般 → 未评级(单列一档) → 中等 → 中上 → 不赖 → 夯 → 创意 → 上等
```

语义依据与假设声明：

- `大雷` = 踩雷（明确负向），放最前。
- `很牢` / `牢`：按「坐牢式枯燥」负向理解，`很牢` 比 `牢` 更差（程度副词在前），故 `很牢` 在 `牢` 之前。
- `拉` = 拉胯（负向），在牢之后。
- `一搬` 疑似 `一般` 的错字，与 `一般` 同级相邻，按「疑似错字」排在 `一般` 前一位（尊重目录现状，不合并目录）。
- `未评级` 单独一档，放在「一般」与「中等」之间：多数未评级是待人工评的中游内容，且数量最大（44）但平均价值最低，安排在中段、靠 easy 引擎先跑。
- `中等 → 中上 → 不赖 → 夯 → 创意 → 上等`：正向程度递增。

**如实标注**：「很牢/牢」的负向排序与「一搬/一般」同级假设均为**待用户确认的假设**；若用户纠正语义（如「牢」是褒义「很牢靠」），则只改本节顺序与批次划分，不影响 TSV 内容与验收方法。

批次定义（用于进度汇报，见 ⑧）：批 1=大雷+很牢+牢+拉（5），批 2=一搬+一般（16），批 3=未评级（44），批 4=中等（16），批 5=中上+不赖（10），批 6=夯（19），批 7=创意+上等（7）。

## ⑥ 聪明跳过机制

- **单款超时上限 15 分钟**：审计或真机回放超过 15 分钟未出结论 → 判 `skip`，记 `reason=timeout`。
- **立即建 Issue**：遇加密/私有容器/插件驱动/需逆向 → 在 GitHub 建 Issue 写明卡点现象与**原始报错全文** → 打 `status/卡点跳过` → 继续下一款。**禁止死磕**（单款不投入超过 15 分钟之外的任何逆向时间；想深挖的单独开新任务，不占用验收主线）。
- **已知卡点类型**（遇到即按上流程走）：
  - RPG Maker 插件驱动（加密 www / plugin 混淆）；
  - Unity 自研 binary-skel（GameAssembly + 自研资源容器）；
  - Cocos enc（加密 jsc/luac）；
  - Godot `.pck`；
  - WOLF（WolfRPG .wolf 归档）；
  - Electron / asar 打包；
  - SRPG 类私有格式；
  - 仅 `.rpyc` 无 `.rpy` 的 Ren'Py（编译脚本，需逆向）。

6. **`cmd/library-audit` 为零基础新建**：仓库内目前没有任何该子命令的实现，命令行入口、扫描调度、判定输出全部要从零搭，开发工期必须单独评估，不计入本计划 7 批验收排期；另外 `reports/游戏库验收_任务清单.tsv` 的「引擎」列保留**原始扫描口径**（检测器识别结果直出，含自研/未知等原始标签），与本文档 ② 的统一口径表**不同**，跨表比对时按款逐一核对，不要直接拿引擎名做汇总。
